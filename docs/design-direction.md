# QuanDeck 简化设计约定

当前实现基于用户提供的 Figma 前端，保留红褐品牌色、白底日记、左侧时间线与右侧执行区。对照早期清爽版的阅读层级做减法，所有状态与交互继续使用现有数据模型。

## 信息层级

- 第一层：任务标题、执行状态、完成子任务数与当前动作；主页直接可读。
- 第二层：子任务树、步骤、最新回复、耗时与用量；展开或选中后显示。
- 第三层：历史回复、统计、连接与来源详情；按需打开。
- 主页用细分隔和排版组织内容，避免重复彩色卡片。品牌色用于主要行动，Agent 色用于身份和时间区间，状态同时有文字或图标。
- 顶部保留总览 / 任务 / 成果与已实现的项目切换；右上角圆形头像打开设置。右侧默认显示三个优先执行条目，完整列表只保留一个展开入口。Agent 名单收为底部可展开的图标行。
- 任务详情删除“执行者 / 主 Agent”一行与下游“挡住”信息。任务树保留必要的 Agent 身份和准确回源入口。
- 输入内容后常驻“交给 Agent 讨论”；普通待办仍可直接记录。讨论区只展示已确定、待决定、方案更新与历史，不在本地模拟聊天。
- 首次安装为空项目库，不预置示例项目、任务或 Agent；未验证的能力不得显示已接通。权限与回复在源 Agent 处理。

## 可交给 Figma Make 的深化提示

在当前 QuanDeck 源码和截图基础上深化，不重建信息架构。保持白底、红褐主色与现有图标体系；桌面采用左侧时间线 232px、流动日记正文、右侧执行区 304px，窄屏按日程 / 任务 / 执行切换。把视觉重心放在任务标题、进度和需要用户处理的事项；减少重复卡片、边框、标签和说明文字。主页保留子任务完成数与当前动作，细节展开后再出现。任何 Agent 信息都需清晰区分身份、执行状态和来源链接；运行、排队、待回复、待授权、暂停、取消、失败不可混淆。讨论交给源 Agent，本产品只收集结论并采用到方案。连接、搜索、回源和时间线沿用现有接口，不能用假成功替代后端回执。所有新控件须有明确行为、键盘可用状态和手机布局。未实现入口直接隐藏。深化时保留人工任务、拖拽委派、会话合并、任务树及原有数据，不扩展无关页面。

## 关键画面

1. 主页：计划与实际、清爽日记、任务进度、待处理队列。
2. 新想法：输入“我要去芭提雅”后进入方案，选择讨论 Agent。
3. 讨论交接：准备指令并复制到源 Agent，明确当前尚未自动派发。
4. 讨论结论：记录本轮结论，采用到方案，支持继续讨论。
5. 任务草稿：编辑从方案整理的条目，选择人工或 Agent，建立任务层级。
6. 连接设置：工具、项目路径、检测与测试、经过验证的能力。
7. 手机日记：保持进度可读，输入与讨论按钮均在屏幕内。

## v0.4 项目与成果

总览切换项目 / 任务维度。项目维度展示项目完成进度、待处理状态、人工与 Agent 成果贡献；任务维度显示选中项目的任务状态环图、主任务进度和日程。成果页以任务地图为骨架，用来源占比、内容组成、覆盖率展示实际输出。人工成果与 Agent 回报并列，草稿单独续写，不计入已发布图表。所有图表使用实际数据，空状态只保留新建项目或记录成果的入口。
