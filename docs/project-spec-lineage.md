# 项目规范、任务要求与成果的来源关系

## 产品约定

已确认的方向确定项目范围和执行逻辑。任务要求细化该方向，并保留自己的验收标准和版本。任务交付的文件即使名为 `spec.md` 或“设计与交互说明”，也只是该任务的来源材料；文件名、Agent 的称谓以及成果地图中的展示位置都不能赋予它项目规范的权威。

项目规范是现有成果整合台帐中显式标记 `purpose: project_spec` 的一个 bundle 的已发布版本。每个项目只有一个此类 bundle。未发布草案不生效；普通成果不能靠修改用途改成项目规范。规范没有第二份数据库、自动同步的 Markdown 副本或独立 runtime。

自动拼接成果地图与确定项目规范是两个动作：前者继续由任务/子任务交付自动填槽，未完成的部分留空；后者由用户核对正文和来源后发布。后续任务沿用已发布版本，不再逐次询问相同的规范。

## 实际问题审计

对用户“QuanDeck能力优化”项目进行了只读 SQLite 审计。截图中的“设计与交互说明”对应一个任务成果，具有任务要求版本、提交与 artifact 记录；两个后续 context package 已固定引用其 artifact ID/hash。该项目没有已发布的 integration version，也没有规范用途记录。

因此，它有任务台帐溯源和局部复用，不能称为项目已确认的唯一规范。旧数据不自动晋升。项目 ID、任务 ID、模型输入和用户正文仅保存在本机私有诊断记录，没有进入仓库。

## 唯一真源与投影

- 方向和任务：既有 `goalPlans`、`specs`、任务及提交台帐。
- 规范正文：既有 `integration.revisions` / `integration.versions`，固定章节及来源 artifact hash、review ID、任务要求版本；`bundles.publishedVersionId` 是当前版本指针。
- 变更审计：既有 `integration.events`；移除规范来源必须说明理由。并行保存使用 revision CAS；发布使用 bundle version CAS；冲突通过既有三方合并处理。
- 台帐：`deriveLedger` 增加方向 → 任务要求版本 → 执行固定规范版本的 `specLineage`。旧规范执行产物标记 `requiresRevalidation` 和 stale freshness。
- 黑板：`deriveBlackboard` 投影当前规范 pin 及需要重验的任务，不写入额外的 spec 正文。
- 执行上下文：`buildContextPackage` 固定规范 bundle/version/hash，并包含已发布规范正文。候选附件不会代替这一正文。

这些关系均从已有台帐推导。现有 SQLite 对不可变版本、事件和 context package 的持久化规则继续适用，不另建可漂移的规范表。

## 规范更新与来源更新

发布新的规范版本后，使用旧版本的下游运行和成果需要重验；旧上下文的提交返回 `PROJECT_SPEC_CHANGED`，旧候选不能被直接验收。后续新运行固定新版本。

当前规范的生产来源及其必要来源祖先不因“发布自己参与生成的规范”而自动失效，否则会产生无限重做。该豁免只免除规范版本变化导致的失效；正常的 stale、过期、撤销与任务验收边界仍由原台帐检查。

来源任务重开或另交新版本，不会自动改变已发布规范。界面和新上下文会提示“来源已有后续变化”，继续明确固定原已发布正文，让规范生产任务可以修订，避免规范阻挡修订自身的死锁。只有从已验收的新来源形成修订并发布后，规范版本才前进。

## 界面

规范入口位于项目/任务的成果地图内；不增加独立成果展示位置。默认折叠显示当前版本、所选章节来源和继承链；展开可查看生效正文与来源、创建修订、编辑正文、选择已验收来源、记录排除理由和处理合并冲突。未保存正文不能发布。

替换来源时，对应章节采用新来源正文，用户发布前可继续编辑。历史版本保持不变。附件链接不自动展开为规范正文；这避免将外链或附件的后续改动悄悄替换为已确认事实。

## 验收与边界

任务提交的结构化总结、来源转交、新会话绑定以及后端录入边界，详见[任务记忆与交接约束](enforced-task-handoff-prd.md)。已发布规范保护由版本检查和 SQLite 不可变事实共同执行，不依赖提示词自律。

- 领域回归覆盖：候选与权威分离、唯一 bundle、规范版本固定、不可变历史、下游过期/验收拦截、生产者不自失效、来源修订不自锁、替换理由审计、项目隔离。
- 浏览器隔离数据完成 v1 发布 → 正文修订 v2 → 来源更新与替换 v3；刷新保留版本；320/768/1440/1920 宽度无横向溢出。
- 现有成果地图回归仍验证自动装配、空槽、退回正文、键盘选择、窗口回弹和减少动态效果。
- 当前机制会提示原来源变化，但不擅自推断新旧规范是否语义兼容；内容确认属于用户发布动作。未来可以增加辅助比较，但不得绕过版本和来源边界。
