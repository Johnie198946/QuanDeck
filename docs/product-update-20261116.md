# QuanDeck 任务工作台更新

## 页面与入口

主导航统一为“总览 / 任务 / 成果”。右上角圆形头像打开“我的设置”模态框，按个人资料、本地 Agent、显示、数据分类。任务页保留日程、任务记录与执行区，窄屏页签使用“任务”。

总览用主任务状态环图、一级子任务进度条、全天执行时间线和待处理事项呈现现状。主任务按待处理优先归入一个状态，不把并行分支重复算成多个主任务。实际时间复用时间线区间并集口径。点击图例筛选，点击任务进入成果详情，点击时间段定位原任务。

“读书笔记”是示例项目的名称，不是第二个导航页。配置名单只显示用户保存的工具；可安装工具目录只出现在配置模态框中。

## 同一个任务的三个视角

任务描述要做什么；日程为该任务或某个子任务安排时间；执行事件记录实际发生的时间。三者通过 taskId、workItemId 关联。修改同一项排期更新原日程，不复制待办。等待与暂停不计作运行，恢复生成新实际区间；并行时间按区间并集合计。

当前排期编辑针对已加载日期，预计时长不会当作人工执行实绩。跨日运行的显示由时间线事件适配器切片处理。

## 分析与方法

写下想法 → 交给已配置 Agent 讨论 → 多轮澄清 → 记录结论 → 采用方法 → 整理为任务。原任务的“先分析”复用该任务，不另建同名主任务。讨论在源 Agent 内进行，QuanDeck 汇总结论和采用版本。

每个子任务可以采用主任务方法，或单独分析形成自己的方法版本。人工任务也是正式任务，不要求绑定 Agent。修改方法后，需要明确应用修订到任务，避免悄悄改变正在执行的要求。

## 主子任务与结果

主任务用文件夹图标、较强标题、独立分隔行；下级任务缩进并用连接线表示层级。最近任务仅首先列主任务，展开后可以进入子任务。

成果作为独立页签：每个主任务是一册，顶部按全部／已有成果／待产出筛选，选择任务册后展示任务进度、方法概要和真实完成记录的文档预览。支持逐份选择、导出 Markdown 和回源会话。子任务已有结果并不代表主任务完成。

打开完整看板后保留三个栏目：任务树、任务方法、执行结果。选择任务后同时更新方法版本、预期交付、完成回报和在途执行动态。移动端按三个页签切换，保留当前选中任务。完成结果保留对应执行尝试的来源，不把另一轮执行的回复当作本轮成果。

## 接口和实际能力

业务数据通过 WorkdeckDataSource 提供，HTTP 模式由 VITE_WORKDECK_API 配置。排期接口补充 workItemId，同任务同范围幂等更新。ensureTaskPlan 保证已有任务的分析入口幂等。

本机工具服务单独提供检测、连接测试、讨论打开和源会话打开。讨论打开返回 needsPaste 时，界面复制指令并提示在源工具粘贴。工具的持续执行事件和自动结论回写尚需后端适配；本次界面不将连接测试视作执行成功。

## 待办与每日日程联动（0.5.2）

新待办立即进入日程的“待安排”，按新到旧显示项目、图标和预计时长。此队列从项目任务直接派生，不创建重复任务或虚构时间。选“安排任务”设置日期和开始时间后，队列与日程同步更新；取消安排会返回队列，任务完成或从任务列表移除后退出队列。

仅部分子任务被安排时，主任务继续显示并注明“部分子任务已安排”。主任务已有当天或未来安排时不重复放入队列。设置计划不会开始计时；点击人工计时或收到 Agent 运行事件才记录实际区间，完成任务会结束正在进行的人工计时。

左侧摘要与每日日程弹窗均跨项目汇总，当前项目使用最新任务快照，新建后不需要重新切换项目。
