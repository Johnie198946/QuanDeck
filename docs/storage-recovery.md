# 本地存储、投影与恢复

数据库保存项目事实与不可变历史。每次项目快照写入与后台导出请求在同一个 SQLite 事务中提交；导出工作失败不会把事实回退。`projections/<project>/<snapshot-sha256>/` 保存 `project-memory.md`、`project-memory.json` 以及同源的 `ledger.md`、`blackboard.md`，`current.json` 只在文件写入完成后切换；每个项目保留最近 20 份可重建视图，数据库中的成果与历史版本不受此上限影响。直接编辑导出文件不会修改数据库。

默认项目记忆使用 `quandeck.project-memory.v1` 固定格式，只包含目标背景、已发布规范及来源版本、已确认条件、当前任务状态、任务职责与验收、最新有效总结与交接、阻塞及下一步。它由台帐和黑板派生，没有独立编辑的第三份事实。失效交接明确显示需复核，候选与已验收分别标记；缺失信息保留为空。内部事件、执行回执和用量不进入记忆正文、默认 JSON 或摘要模型输入。审计增长不会改变记忆内容哈希。 完成数与任务进展共用末级任务口径，父汇总和子任务不会重复计数。没有交接中的下一步时，程序只根据当前 ready/blocked/in_review 等状态给出明确标记的工作流提示，不补写业务结论或伪造交接内容。

完整 `export.json` 属于显式私有诊断/恢复材料，需调用 `exportCollaboration(snapshot, { includeAudit: true })`；不再默认生成或交给新会话。已有机器恢复包仍可按旧格式核对。SQLite 备份与恢复保留全部历史，不因精简记忆而删除。新任务固定上下文保留本任务原始要求、已确认约束、已发布 Spec、版本化的前置成果与交接；摘要仅使用当前业务事实，历史已排队摘要也由发送边界剔除事件和旧日志总结。

SQLite schema 3 将每个项目的快照独立存放在 `project_documents` 的一行中。快照包含该项目自己的台帐、黑板、任务、总结、交接、规范版本和执行事实；`documents[quandeck.projects.v1]` 仅保留项目 ID 目录、当前项目与全局 Agent 配置，不再保存所有项目正文。`immutable_facts` 是带项目键的事务完整性索引，并不是额外的一份跨项目记忆。事件、回执和 Token 计费记录不能算作“记忆条数”。

通常的项目变更只序列化、核对和提交发生变化的项目；同一事务追加该项目的新事实及投影请求。目录 revision 使用比较后写入：旧连接不能覆盖新连接已提交的状态；失败时项目行、目录、不可变事实和投影队列一并回滚。不可变历史仍逐项目核对，执行来源的全局唯一约束仅查来源绑定索引。读取单项目通过 `store.readProject(id)` 或可信主进程的 `getProjectSnapshot(id)`；不先读取其他项目。跨项目引用仍必须经过既有交接与权限规则。

首次从 schema 1/2 启动时先保存 `workspace.sqlite.pre-v3-*`，随后在一个事务内核对全部历史索引、迁移项目行、替换轻目录并提升 schema。迁移前后完整内容和事实数量一致才提交；有不一致则保留旧 schema 与文档并报告错误，不能跳过坏记录“修好”。重启不会重复追加迁移回执。旧版应用会拒绝 schema 3，需要使用升级前副本回滚；备份恢复和受控隐私清除同时支持旧格式及分区格式。

当前冷启动仍为现有业务引擎逐项目加载一次完整快照，显式 `listProjects()`、备份和旧格式导出也需要完整库；本次优化没有声称实现全部历史的分页或懒加载。浏览器模式没有 SQLite，继续使用原有本地存储格式。性能证据见 [公开验证说明](release-verification.md)。

投递队列保存待处理、投递中、结果未知、已完成状态。执行者领取时递增代际、持有租约；旧执行者不能覆盖新回执。进程在动作成功后退出时，下次先查询结果。只有执行器明确报告未发生且支持幂等键时才重试；未知结果继续阻塞。该队列仅处理工作台内部投影文件，不替 Agent 执行任务、预订、付款或发送消息。所有任务成果由 Agent 或人工提供，代码只维护记录、索引与文件。

设置中的永久清除先展示影响预览，确认项目 ID 后还有原生确认窗口。删除登记先持久化在数据库目录之外，再删除该项目事实、原始输入、摘要、会话副本、附件、投影及包含该项目的登记备份。引用该项目的衍生项目也会列入预览和确认范围，因为只删引用无法保证生成正文中没有原始隐私信息。该动作与普通任务/项目归档不同，无法撤销。Agent 自身会话、用户自行复制和云端副本不在应用的清除能力内；本功能也不保证 SSD 或系统快照的物理取证擦除。

备份记录数据库与附件的 SHA-256。恢复在隔离目录核对文件、数据库完整性及事实索引，重放本机删除登记，再通过可恢复的改名日志在重启时切换目录。当前数据保留为 `.before-restore` 回滚目录；若该目录已经存在，本次恢复拒绝覆盖。恢复后的运行保持暂停，必须核对源工具后继续。单纯复制旧数据库不能绕过本机已登记的项目清除。

`desktop/storage-maintenance.test.mjs` 覆盖并发领取、迟到回执、实际子进程中断、未知结果恢复、隐私清除、恢复防复活、篡改备份与生成文件。测试只使用临时目录和受控文件执行器。

JSON、本机浏览器存储导入和 SQLite 版本升级会同时保存 `quandeck.storage-migrations.v1` 迁移回执，记录真实来源、前后版本、项目/任务/会话/成果/不可变事实计数以及回滚副本。历史会话缺少来源映射、项目缺少归属或旧完成记录没有验收时只记录数量，不补造来源或验收。`store.migrationReports` 可用于诊断；没有旧迁移证据的数据库不会伪造过去的报告。
