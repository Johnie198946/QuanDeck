# 执行事件与全天时间线

`WorkdeckDataSource.applyExecutionEvent(event)` 是 UI 与后端之间的回执接口，定义见 `src/data/timeline.ts`。现有演示命令也通过同一个区间 reducer 更新，日记、进度、执行状态和时间线在一次快照更新中发出。

## 入站字段

- `id`：源事件稳定 ID；同一事件重放不重复写入回复或时间。
- `sequence`：每个 execution 严格递增的非负整数；快照初始化占用 0，新事件从 1 起。
- `at`：带 Z 或偏移量的 ISO 8601 时间；禁止只传 HH:mm。
- `projectId / agentId / sessionId`：已同步快照中的真实关联 ID。
- `executionId`：独立会话使用 `session:<sessionId>`，子任务执行使用 `attempt:<attemptId>`。
- `taskId / workItemId / attemptId`：子任务必须传齐，且与既有执行记录一致；未知身份返回先同步快照，禁止猜测父子关系。
- `status`：running / queued / waiting_reply / waiting_permission / paused / done / failed / cancelled。
- 可选 `step / tokens / reply{id,text}` 来自源工具回执，不外推进度或用量。Token 是该执行的最新累计值，不是增量；子执行不包含父级用量。

## 时间规则

running 开启区间；waiting、paused、done、failed、cancelled 关闭区间；恢复开启另一段。重复事件 ID、过期序号、倒退时间不改变区间。结束一轮回复本身不意味着执行完成。后端需在断连时停止更新 `timeline.asOf`，并重连后先对账快照再补事件，不能用客户端当前时间冒充源心跳。

`project.timeZone` 使用 IANA 时区，缺省 Asia/Shanghai。时间线按所选快照 `date` 裁切 ISO 区间，跨午夜仍是同一次执行；23/25 小时夏令时日保留真实经过时长。图上使用同一当地日坐标，00、06、12、18 刻度按实际时区定位。计划时长按真实分钟计算。

实际总时长为所有计划实际区间及执行区间的并集，并行不重复累计。协作分钟先按唯一会话合并重复执行片段，再从父会话区间中扣除其子会话覆盖，最后累加各会话剩余区间；并行子会话仍可使协作分钟超过墙钟覆盖。父会话包含子任务的整体跨度不会再次与子任务叠加。按 Agent 的颜色固定，聚焦主任务时重叠执行分配独立细轨，点击色段定位主/子任务。

## 兼容与范围

保留持久化 schema 4，旧任务、日记、合并关系不重置。首次迁移用已有 startedAt、endedAt、waiting.since、lastActivity 生成 `provenance: snapshot` 区间；旧快照没有记录的历史暂停无法反推，后续真实事件区间标记为 `event`。无可关联任务的历史活动保留，但不提供错误跳转。全天和跨日计算已实现；当前日记仍展示已加载日期，跨日期日记导航并未假装完成。

示例源的时钟与模拟状态用于本地验收，不代表已经订阅真实工具事件。真实后端应通过上述接口供给已验证事件；Snapshot.timeline 可以由后端直接还原以支持完整历史。

## 状态语义回归（最终 QA）

源端 `paused` 原样映射到会话、执行尝试和子任务的“已暂停”，不映射为“等待前置”或“失败”；`cancelled` 显示“已取消”，不会自动把任务标为完成。暂停关闭本段，恢复重开且清除旧 endedAt。`queued` 在尝试、子任务和总体汇总中均为“排队中”，不计入 running。仅有暂停分支的总体为已暂停；全部取消为已取消。最近会话也使用同一状态文案，不把暂停/取消归入运行筛选。

公共接口回归覆盖会话暂停→恢复→取消、子任务暂停→排队、只有排队的整体状态、实际运行计数排除提交和排队。

## 待办与排期关联（2026-11-16）

任务行、子任务行和日程侧栏共用“安排日程”模态框，可选择主任务或任意层子任务、今日开始时间、预计分钟与固定/弹性。保存只新增或更新 `PlanItem`，不复制任务或日记记录。范围切换到已有安排时直接载入原时间，重复保存保持原 `id` 和实际历史。

接口仍使用 `WorkdeckDataSource.addPlan` / `POST /v1/commands/addPlan`。参数为 `{ title, kind, start, minutes, taskId?, workItemId? }`；新可选字段 `workItemId` 表示指定子任务及其后代。未指定表示整项任务。服务端必须：

1. 在当前项目与日期内按 `(taskId, workItemId ?? null)` 唯一匹配并执行 upsert，配合现有 `Idempotency-Key` 防止并发重复保存。
2. 校验关联任务和子任务存在且归属一致；时间为有效 `HH:mm`，预计分钟为 1–1440 整数。失败不得变更版本或产生部分写入。
3. 返回同一快照通道，使计划列表、螺旋、日记关联与实际对比同步。实际时间从相同任务/子任务执行区间推导，不从预计时长猜测。
4. 子任务排期只计该节点及其后代，排除父节点与兄弟分支；并行取并集。子任务完成读取节点自身状态，不误用主任务的完成标记。

日程行与螺旋计划色段使用同一 `taskId/workItemId` 定位。在窄屏上选中子任务会切换到执行详情。当前模态框安排到已加载的当日日程，跨日期排期尚未加入；跨日实际执行仍由 ISO 区间按日裁切。手动完成一项人工作业没有足够证据推算开始时间，不能自动当成真实工时。
