# 任务进展轨迹与候选代码审计（2026-11-17）

## 进展体验

任务列表默认用一条紧凑记录显示当前工作、等待原因、交付缺口及最近回执时间。展开后展示方向、执行、交付、验收四个独立阶段，以及 Agent 报告的已推进事项、接下来事项和最近八条事实记录。任务详情、子任务详情及项目总览选中项复用同一投影。

这些阶段不是估算进度条。直接执行的任务可以没有单独的方向讨论；有执行记录不表示执行完成；候选交付不表示验收通过。已确认方向发生修订时，显示当前修订待确认，不沿用旧版确认。暂停、授权等待、回复等待、失败、再次执行、退回修改与过期交付分别呈现。

| 展示内容 | 读取的事实 |
| --- | --- |
| 当前执行与等待原因 | 源会话 / 执行尝试经 `deriveProjectActivity` 的统一投影 |
| 任务状态与分支范围 | 台帐 `deriveLedger`，使用根任务及子任务身份 |
| 已推进 / 接下来 | 当前执行对应的台帐 checkpoint，标明为 Agent 报告 |
| 交付与质量 | 已声明成果地图中的候选、认可、缺口、待修改、需更新槽位 |
| 最近活动 | 执行、checkpoint、提交、验收事实中的时间与可读说明 |

新组件不写台帐、黑板或成果状态，也不存储另一套进度。旧执行的延迟回执可以出现在历史记录中，但不能刷新当前执行的最近活动时间。未经声明的成果不自动填入输出位；未收到回执时显示事实缺失，不补造百分比或预计完成时间。进展文本沿用运行信息脱敏及工具命令摘要。

主列表默认收起细节，键盘可展开。容器宽度不超过 480 像素时阶段改为两列，适用于窄窗口及宽窗口内的窄侧栏。回执时间更新不重复计算整份台帐投影。
