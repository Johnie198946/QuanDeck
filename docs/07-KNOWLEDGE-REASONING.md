# 帮你记与帮你想 · 源码审查、实施与验收

**使用路径**　写下原话 → 选段提问或发到项目 → 在原文旁读回答。想复用自己的做法时，先在「帮你想」从笔记提炼观点，再把做法作为纸飞机的执行标签。图谱另外寻找用户还没连起来的知识。

## 审查结论

| 用户要解决的问题 | 原有能力及缺口 | 本轮处理 |
| --- | --- | --- |
| 知道一句建议从哪里来 | 已保存笔记、问答、改动历史。旧图谱用整篇笔记建线，长文只取首、中、尾 | 逐段提取知识，分别定位原文、用户提问、补充背景、AI 答复和资料引文 |
| 跨领域发现 | 有关键词、链接和数值比较，也会请已连接的 Agent 读笔记。不同词表达同一种方法时容易错过 | 四路找候选，再让 Agent 说明依据、用途、验证方法和适用边界 |
| 长期演进 | 整体指纹可避免相同请求。历史资料取决于手动生成 | 保存后合并更新、复用未变段落，每周轮查历史；用户反馈按证据保留 |
| 把方法交给项目 | 有笔记选段、纸飞机、项目台帐与黑板、结果回执 | 在现有派发中补充多选方法标签和手写标签。共享记忆、并发任务边界与来源回执继续走原项目接口 |
| 碎片化问答 | 已能调外部 Agent。等待文字出现在标题区，宽表越界，上下文选择不清 | 原文位置显示生成进度与排版后的回答。新问题开独立会话；追问跟随该回答，可附选段、灵感卡或手写背景 |
| 管理灵感 | 画布可连线、反向、保存，节点主要代表整篇笔记 | 勾选多篇笔记提炼、按观点选卡、手写卡、网页和文件参考。旧画布继续可读 |
| 编辑与删除 | 已有正文编辑、附件存储、待办和提醒 | 直接粘贴可编辑表格、复制原图；点列表垃圾桶可连同派生资料删除，旧窗口的自动保存也不能复活笔记 |

## 数据如何保存

复用现有个人知识库及其并发写入检查。项目任务只收到选段和选定的方法，台帐和黑板按项目隔离。个人图谱在设置中首个可用的已配置分析连接上运行。外部 Agent 处理文字，QuanDeck 负责索引、校对、排期与接收结果。

| 数据 | 关键字段 | 用途 |
| --- | --- | --- |
| 知识单元 | id、noteId、revision、source、start/end、digest、at、kind、origin | 定位证据并检查版本。区分用户观点、原文中的事实陈述、AI 推断和引用资料 |
| 检索描述 | summary、entities、domain、goal、mechanism、constraint、features | 用带范围的实体名和方法描述找候选。features 有 12 项，分别取 0–3 |
| 推理结果 | key、evidence[]、category、mode、label、explanation、consequence、check、limitation | 一条发现可以依赖多个来源。证据来自原文，解释是 Agent 的判断，验证步骤留给使用者 |
| 分析记录 | chunks、reviewed、round、reviewAt、history、attachmentCoverage | 复用已读材料、轮查旧材料、保存旧解释，记录附件可读范围 |
| 用户反馈 | evidence、result、at | 相同证据即便换一种说法，仍沿用确认或忽略决定。证据变化后可重新提出 |
| 灵感卡与问答 | idea.source / reference、selection、questionRequestId、parentAnswerId、memoryRefs、background | 记录灵感来源、派发时的方法及追问的父回答。新会话使用用户主动选择的背景 |

图谱保存摘要、定位和指纹。展示证据时回读原笔记或附件。笔记本身已有的改动记录继续由原有存储维护。附件正文缓存有上限，删除最后一个引用后释放。用户主动删除笔记时，也清除该笔记相关的图谱历史。

## 如何找出有用的关系

1. **拆开。** 枚举全文、问答、引文和可读附件。按段落或句末切分，长段继续向后读。要求 Agent 提取实体、事实、观点、方法、经验、目标、约束、结果，并引用一段可唯一定位的原文。名称带类型和适用范围，歧义留待核查。
2. **找候选。** 全文检索用分词和词频权重；向量检索比较 Agent 给出的 12 项语义特征；结构检索检查目标、机制和约束；图谱检索扩展到已知邻居的邻居。每路保留自己的名额，并补入跨领域和轮换的历史材料。这里使用可解释的特征向量，尚无独立训练的嵌入模型或专用向量数据库。
3. **判断价值。** Agent 可判断同源、补充、矛盾、复用、创新。分别尝试多跳、类比、矛盾、组合推理。组合与多跳至少需要三个不同的知识单元。只有词面相同、引文不成立或无法给出实际用途的候选应当舍弃。返回零条是有效结果。
4. **核对并展示。** 逐一验证来源、引文位置、版本、外部回执和依据编号。原文或连接在分析时变化则本轮不写入。用户从已有图谱看结论、全部来源、验证办法和局限，重要决定由用户确认。既有记录含糊时，系统可以指出冲突，不能凭空指定哪一方正确。
5. **持续更新。** 默认在最后一次保存 30 秒后检查，合并连续保存。分析中途改笔记时，对来源与模型都没有变化的批次复用本进程已核对的结果，包括判断没有关联的批次。退出进程后沿用最后一次完整保存的图谱。每小时检查是否到期，每七天轮查最多 32 个历史知识单元，并为其更换比较对象。退出应用会暂停后台分析，重新打开后检查到期项。与当前问题无关的历史进程不会被带进新问答。

## 验收结果与后续量法

**真实模型发现了什么。** 六篇独立编写的合成笔记包含调度策略、旅行备选、两份入场通知、接驳班次和一张带编号的明信片。真实 Codex 提取 16 个知识单元，给出 4 条候选发现。

| 验收问题 | 实际观察 |
| --- | --- |
| 看得出跨领域的方法吗？ | 把服务调度的连续两次确认迁移到行程改道，同时指出五分钟周期不能直接照搬 |
| 能产生可执行的新办法吗？ | 结合班车半小时一班，建议先确认要换点、再按班次转场；提出用同一日程比较改道次数、总等待和延误 |
| 能找冲突、避开假冲突吗？ | 找出同一入口、同一周六的 16:00 / 17:00 冲突，建议核对生效版本。编号 1700 的明信片没有被连入 |
| 知道推断的边界吗？ | 指出班车是否覆盖这三处活动仍需核对，危险天气下不能等待第二次确认 |
| 稳定性与成本怎样？ | 对相同输入立即重跑复用缓存。首次三次外部推理合计约 7 分 43 秒。两条组合建议部分重叠，发现数量不能直接当作创意价值 |
| 能持续演进吗？ | 控制时间、修改中段、切换模型、并发保存、否决后复查、跨版本迁移和删除均有定向测试；每周轮查采用时钟模拟 |
| 笔记和方法真的进入了项目任务吗？ | 同一预算 150 元，选择预算优先得到 120 元路线、余 30 元；改选少换乘并补充最多换乘一次，得到 160 元直达、超支 10 元 |
| 日常问答会串线吗？ | 真实 Codex 首问约 3.8 秒，追问约 4.0 秒，原生会话 ID 一致。浏览器另验新问、选定参考、手写背景及返回到对应原文 |
| 会阻塞操作吗？ | 本机 2,000 个高度重合的合成单元，后台冷检索 2.88 秒；主线程 10 毫秒定时器最大间隔 12 毫秒 |

**复现。** `pnpm test` 覆盖现有产品回归及确定性样本。图谱重点用例在 `desktop/knowledge-graph-agent.test.mjs`，附件和原文在 `desktop/knowledge-attachment-text.test.mjs`，浏览器场景在 `tests/note-answer-layout.browser.mjs`、`note-clipboard.browser.mjs`、`note-deletion.browser.mjs` 及 `note-question-memory.browser.mjs`。本地已登录 Codex 时，可单独运行 `node tests/knowledge-reasoning.live.mjs` 重做六篇笔记的真实模型评估。真实推理会消耗模型额度，默认回归使用固定样本。

**仍要检验。** 六篇合成笔记不足以估计日常使用的准确率或长期创意价值。扩展盲评时，应分别准备同名异物、同事实不同日期、相同机制不同词汇、缺少关键前提、无关联材料。由评审先标注应发现和应排除的关系，再计算正确关联占比和遗漏数。对每条创新另问“哪一步能试、试完看什么、什么条件下不适用”，记录人实际采纳与事后有效的两组数量，避免用节点或连线总数替代效果。

**平台边界。** macOS 实测可读文字 PDF、扫描 PDF 及图片文字；OCR 和 Office 预览存在识别范围限制。Windows 的图片与 PDF 文本提取尚未实现。现有本地知识库单次写入有 25 MiB 上限，超限会提示并保留原库。大规模真实库和用户自定义 Agent 的实测需要单独记录。
