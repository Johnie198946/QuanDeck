# 项目摘要的固定引用契约

真实项目的后台摘要已成功收到模型回复并记录用量，但保存时报“语义重复必须引用输入中的任务 ID”。原输出契约将 `existingTaskId` 声明为任意字符串，输入台帐同时包含主任务、子任务和内部规划记录，提示没有解释这些标识的差别；保存时才检查它是否为主任务。失败回执只有元信息，原始摘要没有持久化，源端为临时隔离会话，因此不能据此还原具体错误条目。

新的固定输入显式提供 `existingTaskIds`，来自本项目实际主任务且属于输入台帐。输出契约随该输入生成：

| 字段 | 允许引用 | 含义 |
| --- | --- | --- |
| 条目 `taskKey` | 固定输入的 `ledger.key` | 定位主任务、子任务或规划记录 |
| `factRefs` | 固定输入的 `factRefs` | 引用本轮提供的事实 |
| 行动 `existingTaskId` | 固定输入的主任务 ID | 明确关联语义重复的现有主任务 |

子任务标识不能填入 `existingTaskId`，不能截取字符串猜父任务，也不能为了满足格式强行关联。子任务事实仍可通过 `taskKey` 和 `factRefs` 表达。不确定重复关系时省略关联；Codex 严格格式的可选字段使用空值占位，再按原契约转为缺省。空项目不生成非法空枚举；没有可引用事实时引用数组必须为空。旧固定输入没有主任务索引时，按规范键排除子任务及 `planning:` 内部记录。

模型输出仍通过领域校验。未知事实、未知台帐键、子项或内部规划记录冒充主任务均拒绝，保留既有失败与用量记录，不修改任务或历史摘要，不静默修正关联，不自动重发失败请求。

同时修复手动刷新与延迟整理的竞态：立即刷新消耗同项目已排队的延迟计时器，避免校验失败后旧计时器再次发起同版大请求。新的台帐版本仍可触发新摘要。

回归覆盖根任务、子任务、规划行、空输入、严格格式、恶意或未知引用的原子拒绝、失败用量保留、同版不重复请求，以及新事实正常触发。真实失败输入的只读回放得到 29 个台帐键、5 个合法主任务 ID、146 个事实引用，输入未被改写。回放只验证引用范围；未宣称重新调用真实 Agent 已成功。
