# QuanDeck V0.7.0：任务检索与完整成果

状态：本轮开发与验收合同；是否通过以对应源码提交、自动化和原生安装证据为准。真实模型成功链路需单独记录。

## 1. 产品目标

把多个任务的已验收成果整理成一份可查来源、可修订、可比较的完整成果。后续任务先读取简短索引，再按需打开相关成果和源会话；不默认回灌所有聊天全文。保持原有导航，台帐、黑板和后台总结不新增管理页。

旅行示例：交通、住宿、每日安排分别完成后，用户在“成果”内建立“泰国旅行攻略”，选择来源，按天或章节组织内容；发布前确认来源有效、日期与资源安排兼容、冲突已处理。后续只改一天，也保留原版本及其他天的人工编辑。

## 2. 身份与检索

| **对象** | **规则** |
|---|---|
| 任务 | projectId + taskId 稳定；改标题不改身份。子任务继续保留父子关系 |
| 受管执行 | 一次执行一个 runId，绑定要求版本与固定上下文；任务可有多次尝试，不用一个 sessionId 覆盖全部历史 |
| 源会话 | 由工具、connectionId、源 sessionId 联合定位；保留本地业务 sessionId，禁止混为同一 ID |
| 执行关系 | 新增不可变 executionLinks，将任务、受管 run、驱动 run、本地会话、Agent 与源会话串联；源连接失效时保留定位信息，不造一个可用深链 |
| 人工任务 | 无 AI 执行时源会话为空，显示“人工完成”；不生成伪 session、run 或 token |
| 成果 | 固定 artifactId、来源执行、版本／hash、验收与有效性，正文不被后续摘要覆盖 |

Task Memory 是可重建的短卡片，包含任务 ID／标题、目标、结果摘要、状态、来源、要求版本、执行索引与依赖。已验收结果、候选成果和仅有目标必须区分；陈旧或归档状态不能隐藏。查询先精确匹配任务 ID、源 sessionId 等身份，再用标题／目标／正文词项检索。命中卡片可继续打开成果、验收证据和源会话。

当前实现按项目快照建立派生身份／词项索引，返回数量受限；不是另一个可编辑数据源，也不宣称已经采用 SQLite FTS、向量检索或获得毫秒级性能基准。

读取顺序为“项目索引 → 相关任务短卡片 → 指定成果／引用片段 → 必要的源会话”。正文超出预算时返回截断／未覆盖标记和完整来源入口，不把摘要伪装成全部上下文。用户原始约束始终保留在新执行的固定上下文中。

## 3. 台帐、黑板和总结

台帐是追加事实与当前业务状态的权威来源。黑板仅为代码派生的当前状态索引：谁在做、等什么、影响谁、下一个可执行动作。它可从台帐重建，不再维护第二套 AI 编写的任务真相。

项目总结为有来源版本的辅助判断。它不能更改用户条件、完成状态、验收结论或发布版本；迟到总结可留历史但不能覆盖新事实。检索卡片和黑板均引用事实 ID，不要求 Agent 同时完整读取三份重复长文。

## 4. 原待办入口

原文先落盘，再请求用户 Agent 配置列表第一项分拣。手动待办绕过 AI 分拣和改写；人工创建产生的业务事件仍可触发后台总结。首项不可用或不支持时保留原文、明确失败，不切换第二项。

默认提示只显示逻辑标题与必要动作，例如“已创建 · 整理泰国行程”“已关联 · 泰国住宿”“保留记录”“分拣失败 · 重试”。长原因、原文和诊断在展开后查看，不能连续铺开模型解释。AI 自动创建与手动创建都落到同一 Task 模型，不建立两种并行任务库。

## 5. 完整成果工作流

1. **选来源**：选择同项目已验收且有效的成果，固定其 artifact、hash、要求与验收版本。未验收、失效或跨项目引用不能冒充可发布来源。
2. **建草案**：命名完整成果，选择章节／多日时间线等适合内容的组织方式；原成果保持只读。正文可人工编辑，新增说明必须保留人工来源标记。
3. **结构化校验**：依据显式事实键、日期／时间段、独占资源与来源依赖，发现互斥事实、时间重叠、来源失效和缺失信息。事实键应包含必要范围，例如“第1晚酒店”和“第2晚酒店”分别比较，不能把不同天的正常变化当成同一事实。自然语言中的隐含矛盾不声称已全部覆盖。
4. **解决差异**：展示差异来源及受影响章节，用户选择保留、替换、重新编辑或删除草案片段，并说明解决理由。不能通过“忽略全部”把失效来源改成有效。
5. **复核并发布**：要求当前草案版本、当前已发布基线和来源状态仍匹配；存在硬冲突／陈旧来源则阻止发布。用户显式确认语义与内容完整性后，追加不可变发布版本。
6. **后续修订**：从已发布版本分出新草案；当别人发布了新版本，用共同基线、当前草案和最新发布版做三方比较。无重叠变更可合并，同段竞争修改必须处理后再发布。

时间安排按项目时区解释，允许仅日期；填写起止时须成对且为同日区间，跨午夜内容拆为两段。改变项目时区、确认条件、要求或依赖的已验收成果会改变来源基线，旧稿需重新核对；旧发布版保持原文并提示过期。

“发布完整成果”只表示工作台内该版本经过确认，不表示已订票、完成旅行、部署代码或向外部平台执行发布。

## 6. 合并与兼容性合同

| **情况** | **行为** |
|---|---|
| 两个草案改不同章节 | 重基线保留两侧变更，继续记录各自来源 |
| 两个草案改同一章节／删除另一侧已改章节 | 明确冲突；不按最后写入覆盖 |
| 草案保存时 version 已变化 | 返回版本冲突并保留本地未保存内容，读取新版本后重试 |
| 发布时 baseRevision 落后 | 拒绝发布；要求重基线与重新确认 |
| 同一幂等键重复提交 | 返回同一回执；同键不同载荷拒绝 |
| 固定来源被新验收版本取代、要求改变或失效 | 标记陈旧并提示受影响范围；旧发布历史保留，不能静默换源 |
| 同一事实键出现不同值 | 显示两侧来源与冲突值，要求明确选择或修正 |
| 同一天、同一独占资源的时间段重叠 | 提示重叠安排；缺失起止或资源时标明无法完整判断，不伪造可计算精度；不承诺跨时区自动换算 |
| 冲突“处理”后仍满足冲突条件 | 再次校验仍阻止发布，备注不能绕过硬规则 |
| 源任务完成但完整成果未发布 | 两者状态分开；不把任务完成数当作最终攻略就绪率 |
| 已发布版本或源成果被改写／删除 | 应用常规写入拒绝；只能新增修订和追加审计事实 |

代码控制身份、权限、来源、结构化规则、版本比较、事务与发布门禁。AI 可通过首项 Agent 提供语义复核或表达建议；建议必须绑定固定证据并注明覆盖范围，不能自动解决冲突、确认用户决定或修改已发布内容。没有 AI 时，手工组织、结构化检查、人工确认和发布仍可使用。

可选 AI 交叉复核使用独立只读系统请求，绑定 project、draft、revision 和输入指纹。每条发现必须引用已提供的章节／成果，并带可在相应正文中逐字核验的证据；范围外 ID、伪造引文和错版回传不能作为有效复核。草案、当前发布基线、来源或确认条件改变后，旧复核提示过期。一次没有发现问题不代表语义完全兼容；发布仍需人工确认和说明。并发和尝试次数受程序限制，用量未知时如实保留；Token 额度由源 Agent 管理；中断后不盲目重试。

## 7. 前端呈现

在原“成果”区域提供完整成果入口，不新增“协作”一级导航。默认阅读当前有效发布版本，草案、来源和差异通过明确操作打开。

- **章节视图**：完整内容为主，目录及来源序号帮助快速定位；详细源身份按需展开。
- **多日时间线**：仅使用实际录入的日期、时段和地点；没有时间的内容作为待安排条目，不编造精确时间或地图线路。
- **来源覆盖图**：从选定来源到采用章节的覆盖关系，区分已采用、未采用与失效；不能将“采用率”标成任务完成率。
- **兼容性提示**：仅显示冲突数量、类型和所涉章节，展开看两侧差异；颜色之外保留文字和符号。
- **版本比较**：展示新增、修改、删除与冲突，可追溯到来源任务及源 session。
- **导出**：导出完整成果文本和必要来源、版本信息；不夹带无关会话全文或凭据。移动窄屏改用纵向阅读，图表具备文字等价信息。

## 8. 存储与不可变边界

继续使用主进程 SQLite 文档事务。Snapshot.integration 承载集成当前投影；不可变发布版本、事件、回执和执行关系纳入 immutable_facts 校验。草案当前版本、选中来源和未发布编辑可经业务命令更新；已发布版本、源成果、原始用户输入、执行绑定、验收及审计事实不可通过常规接口修改。

备份包含完整数据库和附件，导入／迁移不补造旧任务的源会话与验收记录。业务写入、版本检查与新增不可变事实在同一事务中提交。Git 分支只是应用源码交付流程，不能代替产品内每份成果自己的版本与来源管理。

## 9. 验收矩阵

| **ID** | **场景** | **通过标准** |
|---|---|---|
| RI-01 | 一个任务多次 Agent 尝试 | 任务稳定，多个 run／本地 session／真实源 session 均可分别检索 |
| RI-02 | 不同连接返回相同源 sessionId | 按 connection 与工具区分，绝不串到其他任务／项目 |
| RI-03 | 人工任务无源会话 | 显示人工来源，不伪造执行与用量 |
| RI-04 | ID、关键词与中文短句查询 | 身份直达优先，短卡片有结论／来源／状态，全文按需加载 |
| RI-05 | 重建黑板／检索缓存 | 从同一事实版本可重建，不产生新的任务真相 |
| RI-06 | 自动与手动建任务 | 默认只显示简短标题／结果；原文、错误和长原因可展开 |
| RI-07 | 多个已验收成果整合 | 新草案及发布版包含固定来源，原成果没有被改写 |
| RI-08 | 同时保存同一草案 | CAS 拒绝过期写入，已有成功写入不丢失 |
| RI-09 | 两草案基于相同发布版改不同章节 | 重基线合并两侧修改，来源及人工编辑保留 |
| RI-10 | 两草案同时改或删同一章节 | 出现明确冲突，未解决前不能发布 |
| RI-11 | 酒店／城市等同键事实互斥 | 显示冲突值及来源，修正前不能宣称兼容 |
| RI-12 | 同日独占时间段重叠 | 提示重叠，缺失资源或不完整时段不伪造精度，不宣称跨时区自动换算 |
| RI-13 | 上游来源失效或要求改变 | 草案及已发布版本出现影响提示，旧历史仍能查看 |
| RI-14 | 发布时基线或来源变动 | 原子拒绝陈旧发布，要求重新核对，不静默覆盖最新版 |
| RI-15 | 重复发布／同键换载荷 | 相同请求幂等；不同请求拒绝 |
| RI-16 | 直接篡改发布历史、执行关系或源成果 | 存储完整性保护拒绝，整个保存回滚 |
| RI-17 | 泰国多日完整攻略 | 可阅读完整正文、按日查看实际安排、查看来源覆盖并导出 |
| RI-18 | AI 不可用／首项不支持 | 手工整合可用；保留原文，不自动换 Agent，不伪称语义复核通过 |
| RI-19 | AI 复核错版、伪造证据或复核后草案变化 | 严格核对范围和逐字证据；旧复核变为过期，不自动解决冲突或发布 |

上述是产品验收合同。真实源端成功、纯协议 fixture、领域自动测试、UI 检查和原生安装检查分别记证据，不相互替代。自然语言语义复核的覆盖范围和不确定性必须保留。

## 10. 源码交付与分支治理

本轮用户明确授权合并 main。先在独立任务分支／worktree 开发，完成测试和安装验收后，将已核对提交合入 main，再通过 git ls-remote 验证远端 SHA。治理只清理已合入且不再承载活动任务的冗余分支；未合入提交、活动 worktree 及其他任务改动不得丢弃。发布 tag、版本安装包和完成 manifest 保留可追溯证据。

Figma PRD 同步使用原生 Spec 定位修改并回读验证；不整篇覆盖已有文档、参考来源或评论标记。PRD 文字更新不等于软件已经通过验收。
