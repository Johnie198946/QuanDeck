# 清洁发布与验证

GitHub 源码仅包含产品代码、必要的合成测试、公开教学素材与简洁文档。本机完成清单、运行诊断、真实项目数据、账号配置和个人截图不进入源码或安装包。历史提交和已发布旧包不会因本次清理自动消失；当前树清洁不代表历史副本已删除。

发布经过三个代码门禁：

1. `pnpm release:check` 审查 Git 跟踪文件、敏感文件类别、个人主目录、常见凭据，以及经过审查的图片内容哈希。错误仅输出路径和类别，不输出命中正文。
2. 安装包只允许明确列出的应用入口、构建资源、运行模块和 npm 安装的必要依赖。准备目录和实际打包目录均重新扫描，任何不明文件阻止构建。
3. v0.17.0 起，发布器要求两个平台的清洁检查成功、安装包清洁证明、源提交一致、安装与空白启动验证通过。对外 `verification.json` 仅投影版本、哈希、检查结果和匿名计数，不复制原始诊断字段。

全新用户数据目录从空库启动；不会自带演示项目、任务、对话、Agent 配置或运行记录。示例数据仅供显式测试，已有用户的数据不由安装程序擦除。

回归覆盖污染文件、凭据、个人路径、未审查截图、修改过的图片、应用额外文件、发布证明缺失，以及诊断字段不会流入公开验证文件。真实模型表现与所有设备上的性能不能由合成测试证明；尚未完成的模型质量核验仍保持未通过。

每次实际发布的版本、源提交、安装包哈希及原生验证结果，以相应 GitHub Release 的 `verification.json` 和 `SHA256SUMS.txt` 为准。详细本机诊断仅在本地保存，不作为公开源码的一部分。
