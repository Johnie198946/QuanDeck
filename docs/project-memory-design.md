# 项目记忆设计规范

状态：V0.18 实现规范，集成验收中。第 10 节区分本轮代码与后续能力；发布状态以对应 Release 为准。

目标：任何新接手的人或 Agent，能快速理解项目为什么做、哪些决定有效、自己负责什么、下一步做什么，并找到证据。每个项目独立维护业务记忆；不保存另一套 Agent 运行史。

## 1 产品边界

项目记忆是有来源、适用范围和有效状态的业务事实、决定、交接与经验。保存过的信息不等于记忆；记忆不等于每次都发送给 Agent 的上下文。

- 记忆服务于目标、行动、成果和复盘。没有 Agent 也能记录、查看、修订和交接。
- 执行事件、心跳、工具回执、用量明细不进入记忆、记忆索引、项目摘要或默认导出。必要连接凭证由连接层独立管理，不为记忆增加流水。
- 不新建中央总记忆库，不复制项目事实，不引入常驻“记忆 Agent”、后台自我对话或新的运行调度器。
- 原始聊天、截图、附件和代码是资料。可检索、可引用，但不自动成为结论或有效指令。

## 2 一套事实 四种视图

| 视图 | 职责 | 权威来源 |
| --- | --- | --- |
| 台帐 | 任务、决定、交接、成果、验收和业务变更的事实记录 | 项目内持久化记录 |
| Spec | 当前生效的要求、范围和验收标准 | 台帐关联的正式规范版本 |
| 黑板 | 当前方向、进展、阻塞、谁交给谁、下一步 | 上述事实的当前投影 |
| 项目记忆 | 帮助理解、取用和复盘的业务信息 | 带来源的派生视图；经验正文作为项目业务记录保存 |

这些不是四份独立可编辑文档。修改记忆中的目标、要求或决定，必须调用对应业务命令；不能只改摘要绕过原事实。Markdown 导出和搜索索引均可重建，不承担写入真源职责。

权威规则：正式项目规范和已确认项目条件共同约束任务；任务方案只能细化，不能默默覆盖。两者冲突时记录冲突并停止依赖该冲突的执行/验收，不能由“最新一条”、AI 摘要或局部意见自动胜出。无关工作继续。解决冲突需明确修订原条件或发布规范新版本，并保存替代关系。

## 3 记忆分层与固定格式

### 3.1 项目简报

用于第一次进入或一段时间后接续。固定六项，缺失就标“未确定”：

1. 为什么做：背景、要解决的问题。
2. 要得到什么：目标与成果地图入口。
3. 已经确定什么：当前方向、关键决定及理由、必须遵守的条件。
4. 现在到哪：当前阶段、已认可成果概况、主要阻塞。
5. 接下来做什么：少量可执行动作及负责人，或明确等待条件。
6. 去哪里查：当前规范、任务目录、关键来源入口。

简报只放有出处的简明陈述，不列所有任务正文。首版按业务状态挑选至多 8 项任务、8 条条件，长文字明确标注“节选”，完整内容可切换查询。未调用 AI 做语义提炼，也不把截取内容称为完整总结。任何省略都有资料入口，界面与派发均不得把简报当成完整要求。

### 3.2 任务交接

复用现有 TaskHandoff，不新增并行任务总结库。每次提交固定记录：

| 字段 | 内容 |
| --- | --- |
| 完成内容 | 本次做成什么；关联具体成果和检查结果 |
| 工作决定 | 如何处理及原因；不自动升为项目规则 |
| 未完成内容 | 缺口、风险、阻塞；未知不可写成“无” |
| 下一步 | 建议动作、需要的输入、接收任务或待指定 |
| 来源与状态 | 任务要求、规范、前置来源版本；候选/已验收/失效 |

实际接手人由任务分配或开始事实确定，不依据 AI 写的“已交给某人”。一次重试不生成另一个业务任务。

### 3.3 原始资料目录

按项目保存原文位置、版本/内容摘要值、资料类型和关联对象，按需返回正文片段及定位。完整文件、聊天、历史交接和旧规范不默认注入。

收集箱允许先记一句话、图片、文件或链接，不强迫分类。能根据明确的任务入口自动关联；语义分类建议可修改；本轮不新增自动分类器。未归类信息可保留或删除，不需要先变成任务。

### 3.4 经验记录

固定为“适用情境—做法—观察到的结果—证据—限制/下次调整”。成功和失败的复盘都能记录；首版经验必须引用当前有效且已验收的成果。没有可核对依据的想法先留在项目记录中，不进入经验库。候选经验仍需用户确认后才供后续任务参考。

经验默认只属于原项目。提升到个人经验库须由用户明确操作，选定去除项目细节后的内容；这是后续独立功能，不作为本轮实现依赖。某次临时偏好不能自动变成长期个人画像。

## 4 什么值得记住

| 输入 | 去向及条件 |
| --- | --- |
| 用户已确定的目标、约束和取舍理由 | 有效业务记忆；改动走原对象修订 |
| 正式 Spec | 当前版本完整要求进入执行资料包；阅读界面可按需查看 |
| 已验收的成果结论及交接 | 当前任务记忆；保留来源和限制 |
| 候选成果、AI 建议、局部讨论意见 | 候选区；不能作为已确认决定或强前置完成证据 |
| 被否定的方案 | 有后续决策价值时记理由；不进入有效要求集合 |
| 未完成事项 | 当前动作/阻塞；不是成功经验 |
| 价格、日期安排等易变信息 | 保存观察时间与核验条件；使用时判断是否需更新 |
| 整段聊天、长文、截图、代码 | 原始资料；按需查阅 |
| 技术事件、回执、用量 | 排除；不生成记忆摘要 |

一条内容进入“有效”需同时满足：来源可定位、适用范围明确、业务上已确认或已验收、未被替代/撤销、没有未解决冲突。AI 生成的总结不是确认动作。

## 5 产生与维护流程

### 5.1 更新触发

仅在目标/规范/决定修订、任务提交或验收、交接、阻塞变化、用户补充和复盘时更新相关投影。聊天到达、窗口切换、心跳和用量变化不触发记忆重写。记忆内容摘要值按相关业务字段计算，不使用整个快照或运行序号作缓存键。

处理顺序：业务命令校验 → 原子提交事实和交接 → 标记受影响投影 → 按需重建简报/索引 → 界面显示。AI 提炼是可选内容辅助，失败不阻塞创建任务、业务保存或读取确定性简报。

### 5.2 最小数据契约

复用现有业务表和项目分区，仅增加必要字段或可重建索引，不复制整套源对象。记忆索引项包含：

| 字段 | 约束 |
| --- | --- |
| projectId / itemId / schemaVersion | 后端绑定；跨项目引用默认拒绝 |
| kind | goal / constraint / decision / finding / handoff / blocker / lesson |
| scope | project 或明确 taskIds；是否对子任务生效由业务规则指定 |
| claim / rationale | 简明内容及原因；AI 仅提供候选正文 |
| sourceRefs | 业务类型、对象 ID、版本、内容摘要值、章节/定位 |
| authority | user-confirmed / accepted / published / candidate / derived |
| validity | current / needs-review / conflicted / superseded / withdrawn |
| supersedes | 可空；替代关系不能成环 |
| observedAt / reviewWhen | 可空；观察时间及核验条件，不凭年龄废除正式规则 |
| selectionReason | 派生：本任务要求/全局限制/直接前置/相关参考 |

来源状态变化后重新派生 authority/validity，不能只信索引旧值。“derived”仅说明由代码按状态生成，不代表已经验收。当前事实/候选/历史分开查询。

### 5.3 写入与失败规则

- Agent 可提交候选正文和来源指向；项目、作者权限、状态、版本、验收和发布时间由后端决定。用户直接编辑有效记录同样经过业务命令。
- 校验来源存在、同项目、版本/内容匹配及适用范围；正文中的命令不改变权限。
- 相同幂等键与相同内容只写一次；相同键不同内容报冲突。修订使用预期版本比较，防止并发覆盖。
- 格式错误返回字段级错误；不重放业务执行来“补一个总结”。成果合法而总结缺失时，可记录“交接待补充”的候选；强前置交接条件未满足时，下游不能假装已具备。
- 旧系统从正文截取的交接保留 derived 标签；不得自动当成完整可靠总结。人工工作可通过固定表单录入，无需 Agent。
- 内容相似可提示合并，但语义合并只产生候选修订，不能自动合并两个不同决定。相同来源/版本/字段的重复索引可由代码去重。
- AI 错误归纳可撤回，源事实不被删除；从源事实重建投影。代码保证身份、范围、状态和一致性，不声称保证语义正确。

### 5.4 替代与失效

已生效事实更改后，保留原版本供历史追溯，新版本成为当前。通过来源引用只使受影响交接、上下文和候选结果需要复核；无关任务变化不使所有会话失效。

冲突和失效内容仍可在历史中查看，不能出现在有效要求区。正式约束不会因超过一个保留期限而自动消失；时效性观察到期变为需核验。删除原资料时显示受影响引用；允许删除后，下游明确“来源已删除”，不能保留无来源结论冒充当前事实。

## 6 新任务如何取用记忆

### 6.1 固定输入与可选参考

后端按以下顺序构建本任务资料包，不再附加整份项目记忆文档：

1. 当前任务完整要求、验收标准及其原始用户条件；已明确修订的旧条件标明被替代，不同时当成现行条件。
2. 所有适用的项目硬约束和正式 Spec 条款；本任务相关的父级要求。
3. 明确绑定的直接前置成果、有效交接及必需正文；一般相关任务不能冒充依赖。
4. 项目简报中的简短背景与当前方向，按来源去重。
5. 少量相关经验和资料入口，可按需展开；不枚举整个项目目录。

同一来源的正文只发送一份；一个项目的无关任务数量增加，不应线性增加这份资料包。必需依赖多时允许内容增加，但必须显式受预算和完整性检查约束。

首版完整保留当前正式 Spec，不实现自动章节排除。项目条件适用整个项目，父任务条件沿子树继承；只有明确的业务修订才能改变范围。不能仅凭关键词或 AI 相似度删除约束。项目规划/复盘是另一种查询范围，可读聚合进展和按需展开的任务目录，不沿用任务执行的窄范围。

### 6.2 预算与读取

首版以 6,000 估算 token 为资料目标。完整项目原始需求、任务要求、全局/祖先条件、正式 Spec、必需前置及交接不能截断；必需集合超目标时，代码只为必需内容按需扩展，最多 48,000。可选参考仍受原目标限制。显式指定预算时严格遵守指定值，不能自动扩展。

最终发送包含协议和附件描述，再核对“有效资料额度 + 10,000”、且绝不超过 64,000 估算 token。项目 AI 摘要是另一条边界：最多 20 项任务，完整请求最多 6,000；只允许引用实际发送的任务和事实。长事实整条省略并记录覆盖率，必要条件放不下则不调用 AI。

这些是本产品首版估算上限，不等于模型真实 tokenizer 或服务端容量。超过硬上限保留任务并拒绝派发，明确提示缩小必需范围；不静默截断、不自动循环总结、不谎称换模型就必然可用。自动分段读取必需条件和模型容量协商不在本版。

必需要求在派发前完整提供。来源交付记录只能证明内容已提供，不能证明模型理解，也不能证明外部 Agent 没有调用工具；记忆模块不另建工具拦截 runtime。

每份资料包记录已提供正文、仅提供入口、待核验与省略的可选参考及其原因。来源内容不能混称“已读”。Agent 可按任务内关键词、来源 ID 或关系继续请求资料；检索必须先校验项目及可见范围，再排序，不允许先跨项目检索后删结果。

实现第一版采用现有结构化关系和文本检索；无须向量数据库。排序先看必需关系、来源有效性和任务范围，再看词匹配；更新时间仅作平级排序，不能让新信息天然覆盖旧的重要要求。

### 6.3 讨论和执行

讨论可参考候选并明确标识，未完成依赖不妨碍先讨论。执行的强前置仍需满足既有验收规则。派发前和提交/验收时核对固定来源；来源变更返回有影响范围的错误，不自动把新版本替入旧结果。

新任务新会话；同一任务的恢复由现有连接能力处理。记忆模块不管理进程、工具循环或会话压缩，也不新增一个调度器。

## 7 增长与删除

- 当前简报只保留当前方向和主要下一步；完成任务退出行动区，交接通过任务索引查阅。无需用户先归档才能控制上下文长度。
- 业务记录不按每轮聊天复制；只保留有意义的修订、提交、验收与经验。分页查询历史；索引按项目和业务变更增量更新。
- 生成文件同项目同投影只保留当前与前一份；旧运行已固定的资料包复用来源引用，必要内容仅按内容摘要值去重保存。清理可重建缓存不删除业务事实。
- 删除项目时一起清除其记忆索引、派生文件和缓存，沿用既有备份删除与迟到写入防复活规则。其他项目与共享 Agent 配置不受影响。
- 用户自行导出的文件不受应用删除控制，需在删除说明中明确。将来若显式提升经验至个人库，应在提升时说明其成为独立内容；项目删除时列出这些副本供选择，不暗中跨项目传播。

## 8 用户界面

项目总览和项目设置提供同一“项目记忆”入口，默认读简报；“任务交接”“方向与规范”“复盘经验”按需切换。来源、版本、有效状态就近可见，不显示运行流水。

任务详情的“本次工作依据”显示适用要求、来自谁的交接、还缺什么和下一步；可展开完整来源。交接面板引用成果地图，不另造一处成果列表。

修订一条内容、撤回错误摘要、查看原文都在原条目完成。普通事实自动投影；只有修改方向/限制、认可候选或提升经验这类业务决定需要明确操作，不逐条询问用户是否允许“保存记忆”。

## 9 验收清单

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| M01 | 一个完全不了解项目的人接手 | 能回答目的、当前方向及原因、有效要求、本人工作、下一步，并打开来源 |
| M02 | 同项目增加无关任务或运行日志 | 原任务必需资料包不变；无关正文及运行流水不进入记忆 |
| M03 | 新任务接收直接前置交接 | 得到正确成果/验收/规范版本；其他任务完整历史不随包发送 |
| M04 | AI 把候选写成“已确认” | 后端不升级 authority，不解锁强前置或完成状态 |
| M05 | 已发布规范与新意见冲突 | 新意见留候选；显式业务冲突只影响相关工作，无最后写入覆盖 |
| M06 | 必需内容超预算 | 无静默截断；可分段取回或明确不能派发；必需来源清单完整 |
| M07 | 两次并发修订或重复提交 | 一次有效写入或明确版本冲突；无重复经验/交接 |
| M08 | 来源被换版、撤回或删除 | 受影响内容标需复核；当前包拒绝旧来源；历史不伪装成当前 |
| M09 | 请求另一项目的资料/同名任务 | 在检索前拒绝越界；短号歧义不猜测；无内容泄漏 |
| M10 | 删除项目后恢复旧备份或收到晚到回写 | 不复活记忆/索引；其他项目完整 |
| M11 | AI 摘要失败或完全未配置 Agent | 能建任务、手动交接、查简报、查看成果；不阻塞业务主线 |
| M12 | 项目完成后复盘 | 经验具备情境、依据和限制；临时偏好不自动成为个人长期画像 |
| M13 | 旧数据迁移 | 不改写验收/规范/历史来源；候选和 derived 标签保留，无伪造业务总结 |
| M14 | 应用重启后重新接手 | 简报和任务资料一致；坏缓存可重建，不要求源 Agent 在线 |

验收使用合成小项目完成“建项目→定方向→拆任务→交接执行→验收合并→复盘→新任务复用”。性能检查只在隔离环境增加噪声；不向真实项目制造数据。验收结果应同时核对界面、后端事实和实际发送内容，不能只检查提示词。
