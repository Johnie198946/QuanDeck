# 任务收尾与经验复用 · 0.19

任务页回答三个问题：交付了什么，依据在哪里，谁还需要行动。运行结束、提交候选、验收通过是不同事实。用户点任务标题即可查要求、验收条件、交付及核对意见；无正文的旧任务保留事实缺口。

| 情形 | 主操作和依据 |
| --- | --- |
| 未开始或执行中 | 展示任务与进展，仍可讨论方向、补充资料。 |
| 已有候选交付 | 显示候选正文或交接摘要，就地核对条件、确认或要求修改；只更新选中的任务/子任务。 |
| 已有有效验收 | 显示结果摘要，可查验收依据。没有第二次确认。 |
| 项目任务全部收尾 | 任务清单以交付为主，空闲 Agent 面板与常驻输入不占用主区域；仍可新增任务。项目成果正式发布是独立动作。 |

方向页大纲取自实际内容；空的决定、占位验收话术和没有资料的交付结构不充当正文。历史任务详情不借用“可执行任务”的过滤条件。项目简报限量，台帐索引覆盖全量，黑板只给当前行动；三者都由项目事实生成。

## 怎样复用经验

1. 无成果依据的观察先留在项目内，不发送给任务。有效验收后可以就地记录经验，带入该成果及版本；人工确认后才参与推荐。
2. 对同一版本来源和相同内容做归一化去重。不同结果或适用范围可以是不同经验。直接依赖优先，余量按相关性等信息选取，最多三条；必需原件另行完整提供。少量已知词组可匹配同义表达，不承诺通用语义检索。
3. 下游验收时，用户可对该交付固定上下文中出现过的经验报告有效、需调整或不适用并写原因。没有实际反馈不推定有效。后端复核版本、项目及来源，来自失效交付的反馈不参与排序。经验只作参考，无权改写规范或代替验收。
4. 测试使用隔离合成项目。本人项目、数据库、运行流水与屏幕截图不进入源码提交。
