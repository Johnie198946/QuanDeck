# QuanDeck 0.8：Agent 管理闭环

更新：2026-11-16。以用户最新边界为准：QuanDeck 管理 Agent，不自建任务执行 Runtime。研究、推理、规划、工具操作、摘要及候选成果由用户配置的 Agent 完成；人工内容由用户提交。工作台只维护事实、索引、授权、派发记录、版本及验收，不生成伪装为 Agent 的成果。

## 职责与范围

| 工作台代码 | 用户 Agent | 用户 |
|---|---|---|
| 身份、真实源会话映射、版本、权限、索引与持久化 | 理解需求、检索已授权材料、研究、生成候选内容 | 输入需求、确认条件、配置 Agent |
| 发送至既有 Agent 的薄适配、同步公开回执 | 在自身执行环境使用工具、管理自身会话 | 决定派发、权限审批、验收 |
| 确定性冲突检查、旧版本保留、原子切换采用版本 | 提出合并草案、语义复核意见、下一步建议 | 处理冲突并发布完整成果 |

源码中的 `Run`/`runtime*` 保留为既有 Agent 的一次尝试及连接适配命名，不表示新增执行引擎。没有自建模型、任务工作进程、付款/预订/发布执行器或自动代替用户完成验收。内部 outbox 仅将项目投影可靠写成文件，不执行 Agent 的业务任务。

## 身份、读取及上下文

- `projectId + taskId (+ workItemId)` 是稳定任务身份；每次尝试单独保存内部执行、会话、`tool + connectionId + sourceSessionId`。重试和换 Agent 追加记录，人工任务不伪造会话。
- 新派发固定任务目标、验收、用户硬条件、来源版本和实际发出的上下文哈希。必需前置成果完整带入；超预算直接拒绝，不能静默截断。可选成果明确标记截断、全文长度、哈希和下一页位置。
- Agent 可用专属只读凭据按需展开固定资料。每页最多 4000 字符；项目、上下文、执行代际、要求版本、租约和来源有效性逐次核对。普通桌面命令凭据不发给 Agent。
- 每次已交付片段保存不可变读取回执；首包加分页输入的估算不得超过本次上下文预算。此限制只覆盖 QuanDeck 提供的资料，外部 Agent 自身工具输出与完整窗口仍由 Agent 管理。
- 系统分拣、标题和机器摘要使用用户配置列表第一项。首项失败或不支持时保留原文并提示，不静默使用第二项。

## 台帐、黑板与修订

SQLite 项目事实与不可变事实索引在同一事务保存。黑板是同源的当前索引，没有独立协作页面。后台自动生成 `projections/<project>/<hash>/{ledger.md,blackboard.md,export.json}`，写完并校验后更新 `current.json`。仅保留最近 20 份可重建视图，数据库成果与验收历史不因此删除。

设置中的「批量修订任务」导出独立修订文件，允许修改目标和验收条件。导入先展示逐项前后差异，再由用户采用。项目版本、文件摘要、任务身份或不允许修改的字段变化均拒绝；采用追加要求版本，不覆盖旧要求或成果。直接修改台帐文件不会写回数据库。

## 管理层接续与授权

- 接续默认关闭。用户选定根任务和累计新增任务上限后，仅登记已验收任务的 Agent 建议；要求版本、依赖、预算与重复计划均校验。新任务不递归扩展授权范围，不创建执行或源会话，用户仍将任务交给 Agent。
- `autoStart=true` 被拒绝。自动登记不等于自动执行、自动复核或自动接受成果。
- 跨项目复用需显式选择当前已验收成果版本和目标项目；界面默认 7 天有效。只读凭据绑定具体 Agent 尝试与授权版本，源成员、授权、资料完整性、依赖有效性逐次检查。
- 撤销或来源失效使关联成果与传递依赖重新校验，旧证据保留。凭据不返回完整来源项目或聊天历史。

## 成果、用量和恢复

候选、验收、采用版本相互分开。多任务整合沿用固定来源、三方合并、CAS、同键事实冲突与时间重叠检查；已有成果页提供正文、按日安排及来源覆盖。语义判断由 Agent 提供，代码不冒充语义复核。

用量只记录真实 Agent 适配器回执。讨论、执行、复核及后台分析分别计数；累计值去重，迟到与最终用量分开。未返回 token、缓存分类、金额或币种保持未知。设置可导出验收率、人工干预、首包和展开资料量及实际用量报告，不能把未知金额算作零。

隐私清除先列出项目、受影响关联项目、附件、会话及已登记备份，再经输入名称和原生确认清除。独立删除登记先落盘；崩溃后继续清理，恢复旧备份也重放删除记录。用户自行复制、外部 Agent、云端副本不在本机控制范围。恢复校验清单和不可变事实、保留回滚点、暂停旧 Agent 尝试，不重放业务操作。

## 验收证据与边界

| 项目 | 已有证据 | 不能据此声称 |
|---|---|---|
| 代码保留条件 | 20 个标注场景、100 个必需标签零遗漏 | 模型对任意任务均不会遗漏 |
| 历史规模 | 固定合成集 100→1000 项，首包 3327→3327 估算 tokens | 任意数据量或外部 Agent 完整窗口固定 |
| 数据可靠性 | SQLite、实际子进程退出、文件回执丢失、恢复及擦除回归 | 任意第三方服务恰好执行一次 |
| 原生界面 | 任务接续保存零执行、授权与数据入口、不同窗口宽度 | 所有模型/所有机器环境都可用 |
| 真实 Agent | Codex 实际分拣成功，报告仅在本地保存 | 20 条件语义对照及完整成本链已通过 |

真实验收记录一次分拣成功（6406 tokens），另有请求在 120 秒超时，受理或费用未知；后续全量模型质量、全历史对照与总结未完成。它们保留为失败/未执行，不能用确定性测试或安装包检查替代。详见 [公开验证说明](release-verification.md)。

安装包交付需同一提交构建 Apple Silicon Mac、Windows x64，并分别通过原生安装、启动、维护检查和卸载。发布清单记录来源 SHA、包哈希和每个平台证据。
