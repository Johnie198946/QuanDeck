# 固定上下文、按需证据与实际用量

## 本次行为

台帐和黑板继续由事实派生，不新增协作页面。新执行只装入当前任务、已确认条件、检查点和相关成果，不复制整个历史对话。

- 前置任务成果属于必需证据：必须完整装入。超出预算即拒绝装配，要求拆分任务或增加预算，不截掉尾部条件。
- 显式指定的资料不存在、未验收、已失效或遗漏前置成果时，返回错误，不能静默跳过。
- 其他相关成果最多装入 8 个，每个最多 2000 UTF-16 字符。截断时正文明确标记“未完整提供”，附固定成果 ID、哈希、已读偏移和总长度；只有真正进入输入的资料才列入来源。
- 机器可以通过受限证据接口分页读取该次上下文固定的版本，每页最多 4000 字符；不得把未展开内容说成已经核验。
- 项目总结作为非权威建议完整装入或整体省略，不再截断 JSON。
- 任务卡检索支持固定查询及事件水位的游标分页。改变查询范围或业务水位后，旧游标失效。

## 受限证据接口

纯查询函数 `readContextEvidence(snapshot, request, trustedBinding)` 的请求格式：

```json
{
  "projectId": "project-id",
  "contextPackageId": "context-id",
  "artifactId": "immutable-artifact-version-id",
  "hash": "sha256-from-context",
  "offset": 2000,
  "limit": 2000
}
```

`trustedBinding` 是网关从认证凭据取得的 `{runId, claimEpoch}`，不接受调用者用请求正文自报身份。网关还必须执行撤销检查和本次运行累计读取预算。查询层逐次验证当前运行、执行权、要求版本、租约、固定上下文、成果哈希、验收状态及传递来源有效性。接管、条件变化、撤销/过期成果后不能继续读取旧凭据。

返回 `text、offset、endOffset、totalChars、nextOffset、hash、version、sourceIds、sourceRefs、observedAt、expiresAt`。偏移以 JavaScript UTF-16 字符位置计数，下一次使用服务端 `nextOffset`；拼接全部页后的正文哈希必须与固定来源一致。接口只读，不提供全局数据库或用户目录权限。

## 用量和费用边界

`Snapshot.usageAccounting.receipts` 保存适配器报告的累计回执。每条记录包含项目、运行、序号、提供方、用途、时间、总 tokens，以及提供方能够实际报告的输入/输出/缓存分类、模型金额、工具金额和币种。

- 相同回执 ID 与内容幂等；相同 ID 不同内容拒绝。终态回执不可覆盖，历史回执保留。
- 汇总取每个运行的最新累计回执，不累加多个累计采样而造成重复计费。
- 金额用币种最小百万分单位整数存储；不同币种分别汇总，不暗中换汇。
- 未报告的金额和缓存拆分保持未知，不用价格表或模型输出估计实际账单。
- 系统分拣、标题、总结、成果交叉复核在实际适配器调用结束时落账。即使模型内容无效，已独立验证的提供方用量仍保留；回执不匹配的用量保持未知。
- 业务执行由运行适配器回执接入同一记录；不开放 AI 文本或通用业务命令填报实际费用。
- 质量报告统计验收、首次通过率、人工干预和上下文输入，并列出没有对应回执的历史运行。存在未知金额或缺失运行时，不能称为完整总成本。

## 可复现验证

`tests/context-acceptance.test.ts` 含 20 个独立标注任务，覆盖 100 个目标、否决、验收和证据尾注。必需条件遗漏为 0；超预算与缺少必需证据必须拒绝。分页重建检验原文哈希，并覆盖越项目、错误上下文/哈希/代际、已接管、失效资料和超大页请求。

本机 100 与 1000 项历史对照均为 3327 估算输入 tokens，增长 0%；作为对照，全部成果正文估算输入为 83678 和 769478 tokens。1000 项时索引约 30ms、检索约 25ms、装配约 11ms。耗时仅是本次机器观测，不是跨设备服务级别保证。完整测量保存在 `docs/validation/context-benchmark-20261116.json`。

这些是确定性的装配、检索和边界验收。它们不证明模型语义理解零遗漏，也不代表真实模型费用或全链质量基准。报告显式保留 `fixtureOnly=true`、`modelQualityMeasured=false`。真实模型质量和费用必须用实际回执及人工评分另行衡量。
