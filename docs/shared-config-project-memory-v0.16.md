# v0.16：共享 Agent 配置、项目记忆与桌面性能

本次纠正 v0.15 的范围：应用配置是所有项目共同使用的设置，项目无需维护或手动修复一份配置。项目业务记忆、目录和任务身份继续独立。

## 配置与执行边界

- 头像和项目中的 Agent 设置打开同一编辑器，保存同一应用配置。项目表单只设置名称、目标、目录等项目属性。
- 工具、程序、模型、参数属于应用；项目目录属于项目。新执行、新讨论、重试创建的新执行使用当时最新应用配置。
- 后端在执行前解析应用配置与项目目录，建立或复用对应 transport 缓存。缓存不是第二份可编辑的项目配置。
- 正在运行的会话及其回执、附件、续聊固定原连接身份；更新全局配置不迁移旧会话、不重发旧任务。新的配置验证失败时显示失败，不静默使用旧设置。
- 保存应用配置不遍历所有项目握手、不启动模型业务请求。项目无需“使用应用配置修复”。账号与权限仍由源 Agent 管理，不承诺永久取消源端鉴权。

## 一项目一套记忆

v0.15 的 6,624 条是当时七个项目全部不可变事实的合计，并非一个项目的摘要数量。本次只读盘点的八项目共有 6,812 条，其中 3,144 条执行事件、2,625 条回执、541 条用量收据；摘要版本 82 条、结构化交接 10 条。审计记录、业务成果与记忆摘要需分别解释。

旧实现虽然逻辑上带 project ID 隔离，物理上仍将所有项目快照写进 `quandeck.projects.v1` 的大 JSON。v0.16 使用按 project ID 独立存储的快照行与轻量应用目录：修改项目 A 只序列化和写入 A，不重写 B 的历史。SQLite 仍是同一个本机数据库，便于原子提交和备份；这不意味着跨项目共享业务上下文。每项目台帐、黑板、Spec、总结、交接及导出目录均独立。

原不可变事实保留 project/collection/id/hash 约束。迁移具备事务和可恢复副本，不删除历史来换速度。新任务只固定本项目正式规范、任务索引、必需来源与交接；跨项目资料仅可通过已有明确授权的引用机制读取。黑板依旧是该项目台帐的投影，不维护第二份规范。

## 性能路径

1. SQLite 将全库 JSON 快照拆为单项目记录，正常业务写入只处理发生变化的项目。
2. 主进程附件、规范、上下文和导出读取指定项目，避免先 `listProjects()` 再找一个项目。
3. 桌面启动完成迁移后不再把全部业务库回传并复制到浏览器 localStorage。业务存储由主进程持有。
4. 原生更新改为轻量失效通知；前端合并刷新请求、按游标获取变化项目，避免同时推送完整快照并再读取一遍。
5. 桌面渲染器不再额外实例化一个浏览器本地仓库；未变化的总览模型和 Markdown 保持可复用。
6. 外部 Codex 会话发现只读取外部会话。已由运行事件流管理的会话不再每分钟重新读取全部历史，仍可发现同目录的新外部会话。

冷启动仍会加载已有项目，各项目自己的大型历史仍有处理成本；本次不是无限规模的全量懒加载。性能结论以同一真实数据副本的对比及本机验收为准，不能把工具调用等待时间当作纯页面渲染时间。

## 验收契约

- 应用设置与项目入口显示同一配置；无需每项目修复；改变全局设置后另一个既有项目的下一次执行使用新配置。
- 已运行或历史执行保持原 transport、来源与附件目录，新配置失败不回退至过期设置。
- 单项目修改不改变其他项目的持久快照、摘要、交接或不可变事实。
- schema2 升级、重启、备份恢复、并发更新和隐私清理均保留一致性。
- 真实数据旧事实逐 ID/hash 对比不得缺失或改写；项目与任务不因迁移新增执行。
- 原生任务、方向、成果及设置操作成功；同时记录安装版本、源提交、验证范围与限制。

具体执行结果见本任务 completion manifest；未有证据的检查不标记通过。

## 本轮验证结果（2026-11-17）

- 全部领域测试、329 项 Node 测试、TypeScript、生产构建及 46 项发布校验通过。
- 同一真实数据副本、15 轮对比：单项目提交中位数 112.314 → 15.052 ms；单项目读取 48.956 → 4.393 ms；每次提交序列化 11,672,311 → 1,205,968 bytes。其他七项目字节与版本保持不变。
- 会话定位的 50 轮副本测试中位数 35.57 → 0.974 ms。原生通知从约 1.19 MB 完整快照改为约 66 bytes 的失效消息。
- 本机从 0.15.0 升级到 0.16.0，SQLite schema 3。八项目均保留；基线 6,812 条不可变事实在索引与项目快照中逐条 SHA 一致，缺失和改写为零。实际迁移回执是 6,904 → 6,904；额外 92 条事件/回执在迁移前已存在。
- 头像入口与项目 Agent 管理均打开同一“配置应用 Agent”；Codex 与 Hermes 显示所有项目共享；项目表单已无独立连接修复。空验收项目直接显示共享配置可用，未逐项目重新配置。
- 既有交付项目仍显示 2/2 必需成果已验收、项目规范 v1、发布 v1；总览、任务、成果、项目设置及 Agent 编辑器均可操作。该轮未新增模型业务执行。
- macOS 主进程观察到的 physical footprint 从旧进程 1.1 GB 降至新进程 565.6 MB；进程寿命与采样交互不同，仅作为实机观察，不能当成严格内存基准。
- 兼容旧配置已经自动共享，不要求再次保存；真正参数冲突时才显示一次应用级选择。

升级前应用及完整工作区留有本机回滚副本。降级必须同时恢复升级前数据库，不能直接让旧版打开 schema 3。公开安装包、远端 SHA 与最终原生构建来源见 completion manifest。
