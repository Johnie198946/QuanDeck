# 十八、连接可用性与任务接管（V0.7，2026-11-16）

本章对应用户新增要求：DSH 配置归一、自定义连接、启动前检查、执行中异常提醒及备用 Agent。前文任务真源、人工任务、方案、成果、日程和实际用量规则不变。这里定义产品合同；测试夹具、真实厂商联调和安装包交付分别记录，不能因文档已更新就宣称连接能力全部通过。

## 18.1 入口：保留 DSH，新增自定义连接

**决定：两种入口，共用同一套连接、检测和接管能力。** 普通用户在“头像 → 本地 Agent → 配置 Agent”选自己的工具；企业封装、多个模型配置或特殊安装位置使用“自定义连接”。不会把所有人都引导到高级表单。

| **入口** | **填写与行为** | **连接成功的依据** |
|---|---|---|
| DeepSeek Harness / xLink 桌面版 | 选择程序入口和项目文件夹；按需选择服务商与模型。内置“Manage dsh Command → Install / Repair → 重开终端验证”的教程，能自动发现时不要求用户手打路径 | 检测真实 CLI 版本并完成支持协议的握手；桌面版固定启动包装只按已验证模板处理 |
| 自定义连接 | 名称、兼容工具协议、程序位置、项目文件夹、模型；同一协议可以保存多个独立命名配置 | 仍调用相应真实适配器；名称、图标、程序存在或网页能打开都不能替代能力验证 |
| 企业 Web 界面 | 保留界面地址与诊断入口；地址只用于打开和识别服务 | 没有厂商公开协议与真实验证时，不启用任务委派、自动续接或备用能力 |

PowerShell 是终端，不是 Agent 连接地址。xLink DSH 的桌面程序、dsh.cmd 入口、SDK 内核版本和 Web UI 是不同对象；支持情况按实际内核与协议判定。企业包装与上游不同的部分必须单独验证。DSH rc.2 支持的同进程多轮不等于退出后的会话恢复；不支持的权限回传继续隐藏或禁用。

每个命名配置持久保存独立 agentId 和 connectionId，避免“两个 DSH 模型配置”覆盖成同一 Agent。任务保存实际使用的配置；修改默认工具不改历史归属。凭据沿用工具自身的登录或凭据存储，不写入任务、交接摘要或通知。

## 18.2 可用性：看得到的才标已确认

连接状态分为“已具备启动条件”“暂时不能开始”“还有信息待确认”。每次检查同时显示检查时间，不能把过期绿色状态当作此刻可用。

| **检查项** | **能确定什么** | **不作出的承诺** |
|---|---|---|
| 程序 | 真实程序存在、可启动、版本与协议可匹配 | 能启动不等于能调用模型 |
| 项目目录 | 目标目录有效、范围与已绑定项目相符 | 不扩大到其他项目或父目录 |
| 连接 | 本地进程／SDK 握手得到有效响应 | 握手成功不代表网络和模型一直在线 |
| 登录 | 适配器有真实账号接口时读取结果；没有接口标待确认 | 不从“程序正常”猜已登录 |
| 模型 | 收到源端实际响应／拒绝时才建立本次执行事实 | 未发送真实模型请求前，不显示模型测试通过 |
| 可用额度 | 源端提供明确额度／拒绝证据时展示；无接口标待确认 | token 消耗不是账户余额，不能推算剩余额度 |

启动前检查不自动发送收费的模型试用请求，不擅自修改用户项目。没有余额或模型探测接口时，仍可在明确“待实际请求确认”的情况下启动；首个真实请求返回的登录、额度或模型错误必须立即归类并提醒。产品不显示虚构的“全部健康”百分比。

每次派发先持久保存意图，再检查当前连接与目录。检查失败且没有获准备用时，保留待办与失败记录，不显示正在执行、不累计用量。双击和重复请求仍按原 dispatchId 去重；再次主动执行才生成新的意图。恢复旧会话不能偷偷改成另一个配置。

## 18.3 运行监测：分清失败、等待与不确定

本地运行服务在窗口关闭后仍接收源端公开事件。观察进程退出、协议断开、源端报错、公开输出、步骤、工具活动、用量与最后活动时间。仅凭操作系统“有网络”或进程“还活着”不能判定模型可用。

| **情况** | **用户看到的说法** | **执行处理** |
|---|---|---|
| 登录或凭据失效 | 需要重新登录 | 保留进展；引导登录和重新检查 |
| 额度不足 | 可用额度不足 | 不反复重试；补额度或选择备用 |
| 服务繁忙／限流 | Agent 暂时忙不过来 | 提供稍后检查；不无限重发任务 |
| 网络或服务连接中断 | 暂时连不上 Agent | 标记同步／执行证据的实际缺口；不凭断网推断任务已停止 |
| 模型明确拒绝 | 当前模型暂时不可用 | 引导模型配置或备用工具 |
| 子进程异常退出 | Agent 已意外退出 | 保存已收到的进展，提示处理 |
| 连续 3 分钟没有新活动 | 这项任务有一阵子没更新了 | 仅为关注提醒，保持源端状态；不自动停止、失败或重派 |
| 等用户回复／授权 | 等你回复／等你允许 | 排除无进展检测；不能误报卡住 |
| 请求结果未知 | 还不能确认任务是否已开始 | 先核对源会话，禁止盲目重发或自动换人 |
| QuanDeck 与本地服务断连 | 进度暂时无法更新 | 保留最后同步的记录；不改真实任务终态 |

无进展提醒恢复后自动解除；停止、关闭提醒、点击“已读”均不代表完成。任务方法、步骤、已收到的回复、成果、时长和 token 均继续归属原执行，不因故障或接管清零。提醒事件本身不延长实际工作时间。模型输出中的文字不充当权限回执或安全完成证据。

## 18.4 通知交互：让任务继续向前

新增右上角铃铛，承担异常收件箱；不恢复已经删除的顶部运行数字。未配置 Agent 的干净安装保持空状态，不填样例通知。

1. 新异常先以轻量提示出现；任务与应用内提醒始终保留。同一事件不重复弹出。
2. 桌面通知可在“头像 → 提醒”关闭；关闭通知不停止监测，也不删除应用内提醒。
3. 点提示、铃铛或系统通知打开同一“让任务继续向前”模态框，不自动抢走正在编辑的输入焦点。
4. 同时有多项异常时在顶部切换任务，一次聚焦一项；原项目／主任务／子任务定位保持准确。

**模态框内容顺序：**

- 项目名 + 任务图标 + 任务名称；
- 一句原因，例如“暂时连不上 Agent”，下一句给出可做的动作；
- 三点进度轨迹：任务已记录 → 已收到进展／等待进展 → 当前待处理；
- 原 Agent、最后更新、最后公开步骤或回复、已收到用量；
- 操作：“查看任务”“查看会话”“连接设置”“再检查一次”；
- 有同项目可执行备用时，显示“换一位 Agent 接着做”和“预览转交”。

不显示 404、502、堆栈、协议名和内部 ID 作为主文案。不用红色铺满屏幕，也不靠颜色独自表示状态：图标、短标题与按钮共同表达。细线轨迹表示记录位置，不伪造百分比。普通异常使用暖色提示，恢复使用绿色勾；保留白底、QuanDeck 现有品牌色和字体。

桌面模态框宽约 640px，移动端按可视宽度收缩；操作换行、长任务名可折行；原生 dialog 管理焦点与 Escape，关闭后回到触发按钮。检查只更新连接状态，不重跑任务。错误未解除时收起弹层只降低打扰，铃铛仍能找到它。

## 18.5 备用策略：启动前可自动，执行中要交接

每个连接保存有序的备用配置列表。候选必须已绑定同一业务项目、使用同一允许目录、支持任务派发并通过本次检查；仅相同工具名称或相同目录不足以证明获得当前项目授权。禁用、移除、不具备能力或检查失败的候选不可使用。

默认“先问我”。用户显式改为“尚未开始执行时自动换用”后，按列表顺序尝试检查候选。只允许在原任务尚未向模型发送、未受理、没有产生执行副作用的阶段换用；一次派发最多遍历每个候选一次，不能形成循环。备用也可能产生费用，配置时明确使用备用自己的账户。

| **时点** | **自动备用** | **处理** |
|---|---|---|
| 派发前检查明确失败 | 可，且仅使用用户启用的同项目备用 | 重验候选，成功后记录原工具→实际工具与原因 |
| 已受理、正在运行、等权限或等回复 | 不自动切换 | 由用户查看交接内容并确认 |
| 请求是否受理未知、旧进程是否停止未知 | 禁止 | 先核对原会话与执行状态 |
| 只是 3 分钟没有输出 | 禁止 | 提醒关注，允许继续等待 |
| 原会话继续／恢复 | 不自动换人 | 无恢复能力则说明，并提供单独交接 |

自动备用受理后必须展示切换事实，并原子更新实际 Agent、连接、源会话、用量归属与执行者；不把备用的活动记到原 Agent。派发前拒绝不算原 Agent 已工作，不伪造两份用量。

## 18.6 执行中接管：先确认停止，再新建执行

故障接管是本章专用动作；不同于 §6.4 中用户有意保留旧执行的独立协作。此动作必须确认原执行的真实停止／退出，不能因为窗口关闭、RPC 断开或应用重启就认为旧进程已停。停止无法确认、受理未知、外部只观察会话时拒绝自动接管，保留原任务并引导核对。

确认预览展示目标 Agent 及交接范围：原任务要求和已采用的方法、当前任务树、最后公开步骤、最近公开回复、已发布成果文字。附件列出名称；未传文件内容时直接说明。用户点击“确认转交”才创建新会话与新执行，记录前序／后继关系；不可复用原源会话 ID 冒充无缝恢复。

不传密钥、登录信息、隐藏推理和未授权项目内容；原权限批准不转移，新 Agent 按自身权限重新询问。要求新 Agent 先核对已完成部分与工作目录，对无法确认的发布、付款、发送和删除结果先询问，避免重复副作用。

成功后原提醒标“已转交”并链接后继，原记录仍可读；不是“原 Agent 已恢复”。交接失败保留原记录并显示真实阶段，不自动恢复原进程或发第二份任务。重复点击同次接管去重；原已交接会话不能再被隐式回复、恢复或重试。

## 18.7 数据与本地执行责任

所有检测、监测和接管均在桌面主进程／本地连接服务执行，无需额外部署服务器；前端负责展示、选择和明确操作。

| **对象** | **新增合同** |
|---|---|
| 连接配置 | agentId、displayName、兼容协议、程序／项目／模型、真实验证回执；身份与配置版本独立 |
| ConnectionHealth | connectionId、status、checkedAt、expiresAt、checks、canStart、issue；未知不填通过 |
| FallbackPolicy | ask / auto_before_start、有序 connectionIds；派发时与当前项目授权连接取交集 |
| 执行监测 | lastActivityAt、实际状态、停止确认；不以监测时间刷新工作时间 |
| Incident | 稳定 id、原因 code、可读标题／说明／动作、detectedAt、open / resolved、failure / attention、解除原因／后继执行 |
| 备用回执 | fromConnectionId、toConnectionId、reason、明确未发送证据；实际身份与业务执行原子绑定 |
| 接管关系 | predecessorSessionId / successor、原执行停止证据、新 dispatchId、新源会话；公开交接快照 |
| 通知 | 同事件去重、桌面偏好、准确项目／任务／执行入口；持久化失败单独提示 |

本地接口：GET /v1/connections；POST /v1/connections/health；POST /v1/connections/policy；GET /v1/runtime/runs。接管必须走拥有项目与任务校验的业务 handoffSession 命令，不能用裸 HTTP 启动绕过项目绑定。

## 18.8 新增功能与验收

前文 FR-01—44 保留，本次新增如下；与旧合同冲突时以本章关于故障接管、可用性分层及通知的明确规则为准。

| **功能／验收 ID** | **通过条件** |
|---|---|
| FR-45 / AC-48 DSH 与自定义连接 | Windows 桌面 dsh.cmd 与真实 SDK 入口分清；不同命名配置不覆盖；不支持的企业网页不能显示已接管 |
| FR-46 / AC-49 启动前检查 | 每次派发检查；过期结果不复用为当前通过；程序／目录／登录失败时不发送任务；模型／额度未知保留 |
| FR-47 / AC-50 运行异常 | 注入断网、登录失效、额度不足、进程退出、模型拒绝，得到可读原因与保留记录，不伪造完成 |
| FR-48 / AC-51 无进展 | 3 分钟无活动只提醒；等待权限／回复不误报；恢复活动解除；提醒不延长实际时长 |
| FR-49 / AC-52 通知模态框 | 单事件去重、关闭不丢提醒、系统通知准确定位、键盘与390px可用、无技术错误码主文案 |
| FR-50 / AC-53 自动备用 | 只在明确未发送时生效；仅允许当前项目已授权候选；顺序、无环、全部失败、未知受理拒绝及实际归属均测试 |
| FR-51 / AC-54 用户确认接管 | 原进程停止确认后新会话；上下文范围可见、旧记录保留、重复点击不重发、失败／重启／跨项目不串任务 |
| FR-52 / AC-55 安装与实测边界 | 干净安装无样例；本地服务、协议夹具、厂商真机、Windows／Mac 安装分别留证据，不互相替代 |

最小演示：配置主 Agent 和同项目备用 → 新建任务 → 主连接不可用时出现检查说明 → 明确启用启动前自动备用 → 显示实际接手工具 → 运行中无活动触发轻提醒 → 查看保留进展 → 确认转交 → 旧记录标已转交，新执行继续更新。另测受理未知、停止未确认、额度不足及全部备用不可用的拒绝路径。
