## 2. 本地配置

Node 22.15+、pnpm 10：

```sh
pnpm install --frozen-lockfile
pnpm dev --host 127.0.0.1 --port 4173
```

未配置 `VITE_WORKDECK_API` 时，使用 `sampleDataSource` 和已有浏览器本地记录。不会清空此前日记。将 `.env.example` 复制为 `.env.local` 后，可设置已经部署的业务后端基础地址，例如 `VITE_WORKDECK_API=http://127.0.0.1:4180`，然后重启开发服务。4180 只是配置示例，本仓库没有在该端口实现业务后端。

该变量同时切换工作台数据源和搜索客户端。配置后服务不可用会显示错误，不会悄悄回退到样例。`VITE_` 变量会进入前端构建，不能放 API key、配对码或其他秘密。

在另一个终端启动可选本地连接服务：

```sh
pnpm bridge
```

服务默认监听 `http://127.0.0.1:4175`。在界面“连接 Agent”填入服务地址和终端显示的本次配对码，依次检测工具、选择项目绝对路径、测试连接。配对码仅保留在当前浏览器标签页；关闭服务后断开，重启服务后需重新配对和测试。

本地连接服务与业务后端是两个不同服务。不要把 `VITE_WORKDECK_API` 指向 4175：连接服务不提供工作台快照、搜索或业务派发接口。默认允许的前端 origin 为 localhost/127.0.0.1 的 4173、4174；需要其他来源时由宿主配置 `QUANDECK_BRIDGE_ORIGINS`。详细接口及鉴权规则见 [Agent 连接与回源](../src/integration/README.md)。

## 3. 工作台业务接口

实现入口：[httpRepository.ts](../src/data/httpRepository.ts)，完整命令参数和返回值：[WorkdeckDataSource](../src/data/repository.ts)，领域结构：[types.ts](../src/data/types.ts)。后端应遵守这些类型，不另建与 UI 不一致的状态模型。

| 请求 | 约定 |
|---|---|
| `GET /v1/snapshot` | 返回 `{ revision, snapshot }`；snapshot 是完整 `Snapshot`，revision 为非负安全整数、严格递增 |
| `GET /v1/events` | SSE；事件名 `snapshot`，data 为相同 `{ revision, snapshot }`；使用凭据连接 |
| `POST /v1/commands/:name` | JSON `{ args: [...], expectedRevision }`；携带 `Idempotency-Key`；返回 `{ result, revision, snapshot }` |
| `GET /v1/search` | 使用项目、关键词和内容类型查询；详见 [搜索契约](search-activity-contract.md) |
| `GET /v1/activity` | 已提供可选 HTTP 客户端；目前界面使用共享快照推导汇总，不单独轮询此接口 |

`args` 是对应数据源方法的位置参数数组。例如创建事项为 `commands/createIdea`，args 为 `["我要去芭提雅"]`，result 为 `{ taskId, planId }`。加入任务、业务派发、标记完成是不同命令，不能把“建立草稿”当作开始执行。

命令白名单见 `httpRepository.ts`。另有 `navigateToDate`，用于跨日期搜索先加载目标日记再定位；示例数据源没有伪造跨日历史。不要提供接受任意方法名或任意脚本的命令执行器。

客户端忽略小于或等于已接收 revision 的快照。SSE 重连会先重新请求完整快照对账；接口失败显示断连。命令请求超时为 15 秒，当前客户端不会自动重试未知受理结果。后端须用幂等键避免同一请求重复执行，处理 expectedRevision 冲突，并提供查询/对账结果；派发受理未知时禁止直接当成拒绝或成功。

请求使用 `credentials: include`，SSE 使用 `withCredentials`。业务服务负责用户认证、项目授权、CSRF/Origin 校验和带凭据的 CORS；不要依赖前端传入 projectId 作为授权证据。上述服务端能力尚未实现。

## 4. 源会话、回复与子 Agent

前端回源通过 [gateway.ts](../src/integration/gateway.ts)；请求结构在 [contracts.ts](../src/integration/contracts.ts)。源端回执需在 Session、Attempt 或 SubAgentRecord 的 `source` 上提供真实 `SourceReference`：

- `connectionId`、`tool`、`sessionId`：精确连接与会话。
- `attemptId`：区分重试、恢复或更换执行者产生的执行记录。
- `parentSessionId`、`childSessionId`、`childCallId`：独立子会话或嵌套调用的位置。
- `requestId`：正在等待的原始问题或权限请求。

不要用显示名称、任务 ID、示例 ID 拼造源会话。`connectionId` 由连接测试返回；后端应将同一标识注册到业务会话来源，并处理服务重启后的失效。示例模式的回源请求不会访问真实连接服务。

当前 Codex 回源先读 thread 元数据，校验真实 UUID 和项目目录，再请求 Terminal 恢复会话。无法独立恢复的子会话会尝试已验证父会话并明确告知；不会声称已经滚动到子调用。打开源会话不会清除待回复/待权限状态，用户应在源 Agent 处理，由之后的回执更新状态。

`POST /v1/interactions/respond` 已保留请求/响应类型（含 requestId 和 expectedRevision）。本地连接服务返回 501，不代用户回复或审批；未来持有实时请求的适配器才可实现。不能将 HTTP 请求发出当作源端已经受理。

## 5. 搜索、汇总与时间线共用数据

本次实现的是网页顶部汇总及其展开菜单。macOS 系统菜单栏尚未接入；未来桌面宿主应复用同一项目汇总契约，不另起统计口径。

[搜索与项目汇总契约](search-activity-contract.md) 定义模糊查询、命中片段、准确导航、计数去重和可选汇总接口。[执行事件与全天时间线契约](timeline-adapter-contract.md) 定义事件幂等、序号、ISO 时间、时区、暂停/恢复和并行时长。

接收到源端事件后，业务后端应原子更新任务状态、最新回复、步骤、用量与时间区间，再发出一个递增 revision 的完整快照。前端已有 `applyExecutionEvent` 和 reducer 可供适配层遵循；HTTP 客户端仅发送此命令，不替后端实现工具监听。

只有源端提供总步骤才显示完成 N/M；否则显示真实当前动作。Token 使用源端累计数据，未知用量保留未知。一次回复结束不等于任务完成，讨论结束不等于业务完成，主任务也不能仅因一个子任务结束而自动完成。

墙钟覆盖与协作累计不是同一指标：并行时长不重复累加到墙钟；父级整体跨度不能与子级再次重复统计。源端断连时不应持续用浏览器当前时间伪造执行心跳。

## 6. “我要去芭提雅”的当前实际流程

1. 日记底部输入“我要去芭提雅”，点“交给 Agent 讨论”（或 ⌘/Ctrl + Enter）。这一步保存事项并打开方案与讨论结论。
2. 在右侧选择 Agent，再点“交给 Agent 讨论”。弹层提供带目标和当前约束的讨论指令；点击“复制讨论指令”，粘贴到所选 Agent 沟通。
3. 在源 Agent 中多轮明确天数、交通、玩法、照片呈现和旅行计划笔记等内容。这里不承载聊天。复制指令不代表已发送或已派发。
4. 回到“记录 Agent 结论”，填写本轮摘要、已确定、待决定及可选来源链接，保存记录。
5. 点“采用到方案”，确认结论进入方案；人工编辑内容受到保护。继续讨论时重复记录与采用，可保留历史。
6. 将方案明确部分整理为可编辑任务草稿，调整层级与负责人，再加入任务。可由自己完成、交给 Agent 或暂不安排；加入任务本身不会运行 Agent。
7. 普通待办可直接点击“记录”，无需经过讨论。真实派发需完整业务后端及工具适配器受理，当前默认示例只演示状态流转。

## 7. 接入验收

- 接口不可用时显示错误，恢复后按快照对账；旧响应不能覆盖新状态。
- 在真实项目用一个主任务和两个子执行验证定位、独立子会话与父会话回退，不用示例 ID 作为成功证据。
- 源端回复/权限受理后再更新等待状态；测试拒绝、超时和受理未知。
- 对齐日记、顶部、主页进度、右侧执行栏和时间线的同一 revision；测试并行、跨日、时区和事件重放。
- 其他 Agent 工具先按安装版本验收各项能力，再开启按钮；不因为协议名字相同便宣称接入完成。
