# QuanDeck 桌面版

## 使用

- Mac Apple Silicon：打开 `QuanDeck-0.4.0-mac-arm64.dmg`，将 QuanDeck 拖入“应用程序”。
- Mac Intel：打开 `QuanDeck-0.4.0-mac-x64.dmg`，安装方式相同。
- Windows x64：运行 `QuanDeck-0.4.0-win-x64-Setup.exe`，按安装向导完成。
- 首次启动没有预置项目、任务或 Agent。点击“新建项目”，填写项目名称后开始记录任务。
- 需要使用 Agent 时，进入“右上角头像 → 本地 Agent → 配置 Agent”。桌面版自动启动本机连接服务，选择项目文件夹后检测工具、测试连接并保存。
- 安装与登录教程见 [本地 Agent 配置](local-agent-setup.md)。

项目拥有独立的任务、方法、成果与日程。顶部项目选择器切换当前项目；总览的“项目”维度汇总所有项目，“任务”维度查看选定项目内的主任务。Agent 配置可在不同项目间复用，执行记录按所属项目保存。

自己完成的任务也可记录成果：在主任务或子任务点击“记录成果”，填写内容、链接或附件，保存草稿或发布到成果页；发布时可选择同时完成任务。只发布成果不会自动把仍在执行的任务标成完成。

## 本机数据与导出

任务、方法、成果文本和日程使用本机持久存储；附件使用 IndexedDB 按项目保存，单个文件上限 25 MB。退出并重开应用后仍能读取已保存内容。浏览器预览与桌面应用的数据各自保存，不会自动同步。

右上角头像 → 数据 → 导出全部项目，可导出所有项目的 JSON。JSON 包含附件记录但不包含附件文件内容，附件应在成果中单独下载。Agent 的登录凭据与源对话仍由对应工具管理。升级应用保留已保存数据；旧版示例项目不会自动导入新的项目库。

## 分析到执行

1. 新建或进入一个项目，在任务页写“我要去芭提雅”，选择“交给 Agent 讨论”；已有任务使用“先分析”。
2. 选定 Agent 与项目目录。“在 Agent 中开始分析”会打开源工具的交互终端。工具未安装时先完成配置教程。
3. 在源工具中多轮沟通行程天数、交通、玩法、照片与最终笔记。QuanDeck 只保留结论。
4. 把本轮结论记录回来，采用到任务方法，再整理为子任务。每个子任务可交给自己或 Agent，也可继续细分。
5. 总览点击任务，查看任务树、采用的方法和执行结果。未完成的过程显示为执行动态，不计作完成结果。

当前讨论结论通过“记录 Agent 结论”录入。外部会话的自动回写、Token 与执行事件由 `WorkdeckDataSource` / Runtime 适配器提供；本机连接服务尚不实现完整持续同步。Codex 已实现登录与会话元数据校验、准确会话回源和交互讨论打开；其他工具按检测到的实际能力启用。WorkBuddy、DSH 使用手动协作。

## 构建

需要 Node.js 22.15 或以上、pnpm。

```sh
pnpm install
pnpm desktop:setup
pnpm exec tsc --noEmit
pnpm test
pnpm desktop:package
```

也可以运行 `pnpm desktop:mac` 或 `pnpm desktop:windows`。默认目标为 macOS arm64 和 Windows x64。安装包位于源码根目录的 `output/installers`，`output/desktop` 仅保存中间产物。Electron 运行时可由打包器下载，或放到 `output/electron-runtime`；本次缓存均按 Electron 官方 SHASUMS256.txt 校验。

应用使用稳定的 `quandeck://app` 本地页面来源、隔离的预加载接口、随机环回端口和每次启动的随机配对码；页面不能直接调用 Node.js。文件夹选择与连接信息仅暴露给本应用窗口。默认不向非本机地址开放连接服务。

## 安装验证

原生安装、启动、移除与本地服务认证由 GitHub Actions 执行，结果随构建上传。0.4.0 还检查全新用户目录中不存在项目、预置 Agent 或连接配置，并记录 `cleanStartup: true`。检查脚本、签名状态和具体流程见 [桌面安装包说明](../desktop/README.md)。Agent 的真实登录、推理和用户会话不属于安装烟雾测试范围；是否已验证某个平台，以对应构建记录为准。
