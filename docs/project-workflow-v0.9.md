# QuanDeck V0.9：方向、任务与成果

更新：2026-11-17。实现与验收证据见本次 completion manifest；文档中的验收条件不等于已通过。

## 唯一事实来源

台帐记录用户决定、方案版本、任务层级与依赖、执行回执、候选成果和验收事实。黑板由这些事实确定性派生，可重建。聊天摘要、界面缓存和模型输出都不能成为另一份项目状态。

## 两种入口

- **新任务**：本地创建，可手动补充要求、记录成果、拆子任务，或拖入 Agent 执行。创建本身不启动聊天。
- **先讨论方向**：只确定目标、范围、执行逻辑和交付形式。页面明确显示“讨论方案”，用户可继续修改、确认方向，或将明确的小任务直接交给 Agent。

## 项目分解与执行

项目目标 → 方向讨论 → 用户确认方向 → 结构化任务树 → 子任务执行与验收 → 父任务汇总 → 最终成果。

确认方向是本地、带版本校验的业务命令，不通过再发一句“我确认”让模型重复判断。没有任务树时，用户启动一次拆分；返回的任务树绑定已经确认的方案版本，同版拆分无需再次确认方向。修改方向会产生新版本。

任务候选包含稳定键、父项、依赖、负责人和完成条件。整棵树校验引用、重复、循环和父子依赖死锁后一次导入。建议和疑问不会自动各变成任务。重复操作不重复创建。子任务成果尚未验收时，父任务不能开始汇总；汇总上下文固定包含已验收的子成果，不能只依靠聊天摘要。

## 清晰的决定与进度

只在本轮存在新决定或缺失关键信息时展示确认区。已确认信息写入台帐并带入后续上下文；“无其他补充”不产生新一轮空确认。明确区分“确认方向”和“补充信息”。旧会话不得确认另一会话的新结论。

执行显示真实阶段、当前活动、已用时间和最后回执。只有源端提供步骤或完成数量时显示对应进度；否则使用持续活动条，不伪造百分比。等待用户、权限、恢复失败都有明确动作，阶段结束不等于业务任务已验收。

任务标题、结论和成果可直接在 QuanDeck 打开详情；源 Agent 入口作为进一步查看工具和会话细节的路径。Agent 使用自己的标识。内部协议、凭据和工具参数不占据主要阅读区。

## 成果阅读

成果首先呈现标题、重点和可阅读内容。图片、视频、PDF、Excel、Word 使用附件预览；HTML 图文成果支持沉浸阅读、宽屏布局、窄屏回流、展开回弹、Escape 退出和减少动态效果偏好。

HTML 预览禁止脚本执行，保留内嵌照片和静态样式。只读取已登记成果附件，不允许渲染器任意读取本地路径。Google 地图通过明确加载入口单独联网；不将未查询的地图或估算当真实路线。相对本地资源不会未经授权自动加载。

## 删除与额度

删除前展示具体阻塞会话及停止、归档、回源核对入口。操作后重新读取回执，不用仅显示“删除失败”让用户自行猜测。未知受理或不能确认停止的源执行不得被默认为安全结束。项目删除为工作台移除，保留历史资料和源会话。

QuanDeck 不设置或执行 token 额度上限，用量记录只供查看；额度由用户的源 Agent 管理。

## 发布平台与验收

只维护 Apple Silicon Mac 和 Windows x64。发布使用同一 GitHub 提交，核对 main、标签、安装包、原生安装检查及哈希。

核心验收覆盖：零聊天创建任务、一次确认方向、带层级依赖的任务树导入、旧会话拒绝错误确认、未确认停止拒绝重启、子成果完整固定、真实进度、可点击详情、320–1920 像素成果布局和图文安全预览。
