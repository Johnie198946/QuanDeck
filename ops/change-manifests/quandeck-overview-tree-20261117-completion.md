## Goal and implementation

Replace the chart-and-summary overview with a compact hierarchical project/task outline. Both dimensions read the same existing snapshots, business-task projection, workflow, orchestration items, attempts, sessions and result records. Nothing is persisted by searching, expanding or selecting. Existing blackboard and ledger remain authoritative.

Project view initially opens only the current project's root tasks. Task view initially reveals the first level of subtasks. Users can expand any remaining branch, search with its ancestors retained, filter states, select a concise detail view and enter the actual task/result workspace. Project expansion and selection do not switch the active project. Native disclosure buttons, keyboard Left/Right, visible focus, Escape and focus restoration support keyboard use.

Counts use direct children and retain the full denominator under search/filtering. Task acceptance is separate from child completion. Source progress with a denominator appears as exact steps or source percentage; unknown execution uses activity without inventing a percentage. Historical malformed hierarchy is reachable once and labelled for review. Task IDs are scoped by project.

Desktop uses a wide outline plus an on-demand detail column; compact widths use a native modal detail. The design reuses existing palette, real Agent logos, task symbols and settling motion, with reduced-motion support. Management actions are secondary disclosures.
